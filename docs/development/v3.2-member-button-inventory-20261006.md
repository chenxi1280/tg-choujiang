## 1. 统一目标与现有入口

### 1.1 首页目标 G01：五个控件

| 行 | 左侧 | 右侧或独占 | 目标与状态 |
|---|---|---|---|
| 1 | 我参加的抽奖 | 我发起的抽奖 | M01 本人参与列表 / 创建者活动列表；身份与统计分别展示 |
| 2 | 创建抽奖 / 继续创建抽奖 / 查看发布状态 | 独占一行 | 无有效未发布草稿用创建；有效未发布草稿用继续并显示标题及保留期限；会话已绑定发布活动 ID 时看同活动发布状态，不再次创建；三态只显示一项 |
| 3 | 使用指南 | 个人设置 | G02 指南 / G03 地区资料及本人用户 ID |

`/start` 无参数、`/menu`、所有「首页」和「返回首页」必须使用同一菜单。`/new` 恢复有效未发布草稿；会话已绑定发布 ID 时恢复该活动状态页，不能再生成活动。重新创建放在草稿更多设置的「清空并新建」，说明影响并确认。草稿仍按最后更新后24小时保留，进首页不得静默删除草稿或新建替代草稿。C01 返回标签为「返回首页（草稿保留）」，有未保存编辑稿时先明确保存/放弃，不暗中提交。

五控件首页和十控件草稿主面板指普通版面；必要分页、错误说明及同身份恢复入口可附加，不是功能数、活动数或操作轮次上限。

### 3.3 目标：活动详情直接含进度

M02 是本人活动唯一中心，直接展示成员条件、本场门槛及次数；M04 仅为「我的进度」页内区域和旧路由别名，不再建一个重复摘要的中间页面。`member:tickets` 等旧次数入口按同活动身份到该区域；有结果时到 M08 结果区域，不能自动选择最新活动。

| 目标控件 | 直接目标 / 主操作 | 返回与省略选择层 |
|---|---|---|
| 查看门槛进度 | 本场门槛逐群列表；每群正文目标/进度/差值/完成日期，进入本群详情 | 单群直接详情；来源为 M02、具体通知或旧入口时保留该来源，详情回真实群页或活动 |
| 本群发言门槛详情 | 本群条数、连续天数、今日值及已完成事实；可用时「去本群发言」 | 只使用真实已可用的普通群入口；回 Bot 仍定位同活动同群，不重置起点或承诺补算 |
| 本群邀请门槛详情 | 已确认/待核验人数、目标/差值、留存及最晚时间；「我的邀请链接」「邀请记录」 | 按能力显示新入口；无窗口仅查看事实；不进入加成页才能完成门槛 |
| 加成明细 | M05 适用类型及群明细，独立于强制门槛 | 只有一种类型省类型选择，只有一个群省群选择；按 origin 还原活动/来源，不能「返回」再次重定向自身 |
| 我的邀请链接 / 邀请记录 | M06 / M07，包含仅邀请门槛无加成场景 | 保留活动、群、分类、页码和筛选来源 |
| 分享活动卡片 | 取得本人可转发的活动卡片 | 宣传用途不计个人邀请；不替代我的邀请链接 |

活动、邀请聚合和记录列表按完整本人/权限范围服务端逐页查询，冻结群目标按完整manifest分页，不先取前20条或全量记录进内存再切页。重排序、变更或越界明确恢复可定位来源；无匹配保留清除筛选/返回。动作绑定稳定活动/群身份，群升级解析新路由而不重建进度/归因/奖励；同名目标正文完整，序号和必要ID尾号仅用于辨识。

证据：`member_records.py:46–72,171–208`；`member_record_text.py:12–105`。

表中本人状态不得先于活动能力套用。统一判定顺序为：发布状态/终态与真实截止 → 运行阻断及各模块允许状态 → 事件/任务时间窗口 → 本人资格与目标群权限。分别生成登记、发言、邀请归因、留存核验、取新邀请入口、分享、奖励入账与只读查看能力；不能因 `PAUSED`、`SCHEDULED` 或一个故障群一律关闭全部能力。正常群与故障群事实分开展示，必要整体阻断依原服务合同判断，不跳过失权目标强称全场合格。

最终次数和实际开奖时间仅来自已完成 DrawRun 及本人已保存快照；只见 `DRAWN` 标签或历史账本不足以展示最终值。取消未开奖显示未开奖，计划时间保留计划标签；已完成开奖中的未进入名单与 0 次快照不是同一事实。

旧分享请求目前仅回复「分享卡片已提交发送到本私聊；收到后长按卡片转发」。V3.2 操作统一「分享活动卡片」，反馈区分排队、确认、明确失败、未知；收到卡片后保留原生图文长按转发及同活动报名链接。入口旁说明「宣传活动不计个人邀请；计入本场邀请进度请用你的个人邀请链接」。卡片获取不生成个人邀请归因；终态不续发开放任务引导。

中奖页先完整显示活动、奖品名称/顺位/名额和已保存领取说明；「联系发奖人员」打开已有身份，「复制领奖联系信息」只复制本人剪贴板，不自动发送、登记申请或确认交付。精简模板使用实际换行：

```text
活动：<同活动链接>
本人ID：<Telegram ID>
奖品：第<顺位>顺位 / 名额<编号>
```

完整活动/奖品名称继续在正文，复制身份不得靠截断名称识别。多奖品逐项复制，保留同活动身份。[Telegram CopyTextButton 官方限制](https://core.telegram.org/bots/api#copytextbutton)为1–256字符；按实际字符容量核对模板，不把消息正文或整份多奖品说明直接塞入复制控件，具体编码/容量校验沿用统一控件合同，不新增业务名额或奖品长度上限。

证据：`member_record_text.py:12–88`；`member_share.py:4–11`；`member_bonus_text.py:22–78`；`member_activity_landing.py:44–74`。

个人次数和邀请记录路由目前会用 `private_record_message` 转本人私聊；加成分类和群详情直接 `query.message.answer`，缺相同私聊约束。这是静态调用路径差异，未实测所有转发场景或确认已发生泄露。V3.2 个人详情、资格/进度、账本、邀请明细查询及个人归因入口一律本人私聊；群查询按钮只负责本人私聊导航。Telegram 拒绝私聊要明确失败及打开机器人操作，不能群内回退公开个人查询内容。此约束不取消 V3.0 §6 既有本群必要门槛/奖励通知：依 §8.1 发本群数据和用户提及，不扩散跨群完整账本、邀请明细或个人链接。

导航上下文至少包括活动、来源页、活动分类及页码、当前群、群页、记录筛选及页码。返回不固定第 0 页、不默认最新活动。纯导航、分页和刷新编辑当前面板；登记/请求等业务提交有单独回执，真实状态仍从数据库及投递事实读取。旧消息状态过期时明确显示并打开当前同身份页面，不吞错、不伪造送达。

命令或活动深链离开草稿时，保留已保存配置和未保存编辑稿，但终止当前字段文本接收；新的普通文本不得误写刚离开的草稿。回到该草稿时显示保留的编辑状态，只有明确重新进入某字段后才再次接收该字段输入。同活动发布会话恢复看发布状态，不因 `/new`、重复点击或旧首页按钮建立第二个活动。

没有发现成员排名/排行榜的按钮、路由或实现；源码中的活动统计是创建者管理详情的报名人数、有效/待验证邀请、总次数和投递汇总。本附录不把「排名」写成现有能力，也不在本版新增排行榜承诺。管理统计不能证明成员报名、开奖、群公告或中奖私信已完成。
