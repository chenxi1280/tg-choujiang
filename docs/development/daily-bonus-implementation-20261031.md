# 抽奖加成票实现与验证记录

日期：2026-10-31。依据：[抽奖加成票 PRD 开发基线](daily-bonus-ticket-prd-20261031.md)。

## 实现结果

本轮完成代码实现，上海完整回归1769项通过，最后的提醒链接及文案专项32项通过。主功能提交`c615473`已通过标准发布链上线；2026-10-31晚用户另行授权提交、发布与受控真实验收，过程及结果见[生产验收记录](daily-bonus-production-acceptance-20261031.md)。发布前原活动数据已保存并独立比对。当前工作区原有的进度状态标记修改保留；本次发布提交排除这些既有改动。

- 新活动使用 `daily-after-start-v1`，首日不发；从北京时间第二个自然日起，同一活动、用户每天最多获得 1 张发言来源的抽奖加成票。
- 所有开启奖励的群当天条件完成后，自动发放同场 1 张；各群不分别多发。
- 抽奖门槛支持本期累计与每日要求。本期累计完成后不要求每天重新完成累计条数；每日门槛每天重算。
- 抽奖加成票设置增加“双算／不双算”，默认双算、整场统一选择，各群条数分别配置；保存和取消有对应行为。
- 双算同时统计当天门槛与奖励发言，但达到发票门槛后才发票。不双算从完成门槛的下一条消息开始统计，完成门槛的那条消息不重复用于奖励。
- 例：每天门槛20条、奖励要求10条，双算第20条发票，不双算第30条发票；本期累计66条，第一天40条、第二天26条，双算在第二天完成累计门槛时可发票，不双算还需再发奖励要求的条数。
- 已获得的票跨日保留；整场资格未完成时暂存，当前有效次数与累计票数分开展示。暂停、截止、取消和历史查询不引导继续获得新奖励。
- 设置、草稿预览、正式卡、完整规则、群内查询、私聊详情及提醒统一使用抽奖门槛、抽奖加成票、邀请加成票的名称。
- 邀请加成票继续原规则。已发布活动和已冻结发布快照使用原规则；未发布未冻结草稿及复制创建的新活动使用新规则。

## 实现选择

直接改变全局默认计票函数虽然修改少，但不能区分已有冻结活动。采用显式新规则版本，沿用旧版计算分支，仅在新规则中执行首日、门槛和整场每日上限判断。

沿用原消息事实、DailyProgress、追加式 TicketLedger、活动锁及通知Outbox，不建立第二套票数来源。新版本和双算选项保存在原规则JSON中，抽奖门槛的累计模式保存在逐群门槛规则中，无数据库结构变更。

发票沿用已有活动锁串行化，另以活动、用户、日期构成奖励幂等键；消息重放、两群并发、查询及通知重试不重复发票。旧版 `unlimited-v1` 和无新版本标记的活动继续执行原奖励数量和日期规则。

规则能力检查新增每日奖励版本及周期累计门槛能力。数据库中存在新规则时，缺少对应能力的镜像不能通过部署或回滚能力检查。

## 验证

数据库相关验证经上海专用Docker测试执行器运行，沿用原实例身份校验、互斥锁及每个测试进程60秒硬超时。本轮未启动本机数据库或缓存。

新增专项测试位于：

- [设置与冻结策略](../../tests/test_daily_bonus_policy.py)：双算保存取消、固定数量、累计门槛及界面单位、冻结规则保护、旧草稿说明更新。
- [计数与账本](../../tests/test_daily_bonus_integration.py)：首日、跨日、每日上限、双算及不双算、周期累计、多群合计1张、旧活动首日多轮奖励保留。
- [边界与并发](../../tests/test_daily_bonus_edges.py)：北京时间零点、同秒消息、跨群并发、暂停取消、截止后历史、复制设置、单日活动零奖励、邀请门槛独立、晚报名、实际存储规则的镜像能力检查。

阶段验证记录：最初专项13项通过；扩展创建及旧编辑链48项通过；边界专项21项通过；命名与规则修复专项106项通过。上述为不同阶段和范围，不相加充当最终总数。

最终完整回归：`bash deploy/run-shanghai-tests.sh all` 成功退出，8个分片、24个批次、1769项测试全部通过，迁移降级再升级和schema检查通过。

## 四个维度复核

| 维度 | 结论及边界 |
| --- | --- |
| 正确性 | 用真实隔离数据库验证票账本、缓存、门槛边界和奖励幂等；旧活动保留原分支；完整回归结论见上文 |
| 性能 | 复用原活动锁，新增读取限定同一参与者、群和日期或本期窗口；未进行大场容量压测 |
| 可维护性 | 计票、查询和提醒共用每日奖励事实计算；通过冻结版本区分新旧活动，无新增数据库结构或第二套票数状态 |
| 安全性 | 镜像能力检查拒绝不支持新规则的制品；原活动规则、历史票账本及原不可变开奖快照未被改写；受控测试新增记录及审计见生产验收记录 |
