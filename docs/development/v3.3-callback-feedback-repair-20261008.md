# R8 普通按钮回执阻塞修复

2026-10-08，北京时间。基线c147633，线上代码4e8e4b0。R7布局及已保存业务规则保持。

缺陷：`LotteryUpdateHandler._callback`在实际业务前等待无内容`answerCallbackQuery`；除了TelegramBadRequest外，回执网络错误会抛入Inbox并阻塞后续同序事件。R7门槛内部处理371—1159毫秒与完整Update1109—2967毫秒是不同测量，不能直接把差额全部归因于回执；串行依赖和失败路径由源码确认。

规范先更新统一PRD R8 §27。修复仅分离普通按钮回执与当前Update业务，保留原延后结果反馈、身份/权限/token、草稿幂等、同序Inbox、Outbox与业务语义。实施、验证和发布证据继续记录；未验证项不计通过。

本地无数据库回归19项通过（2.77秒），每进程60秒硬超时；477文件格式、Ruff、指标、编译和差异检查通过。上海定向69项通过（9.51秒），迁移及schema检查通过；该轮在新增同时失败清理用例前打包，最新清理用例由本地19项覆盖，并进入随后完整回归。代码审查覆盖：取消任务收回、回执异常与业务异常区分、延后弹窗不被抢先回执覆盖、Update与草稿重试身份、日志继承同一bot/update/release上下文。
