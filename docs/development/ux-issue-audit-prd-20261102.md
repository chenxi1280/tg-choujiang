## 0. 实施总约束

1. **只改展示和创建交互，不改业务语义。** 门槛、加成、计数、资格复核、开奖、Outbox、幂等键、草稿版本与回调 token 校验全部保持现状（见 `AGENTS.md`）。
2. **已发布和历史活动：规则事实不变，文案按本稿调整。** 历史活动继续走原规则分支，统计模式、阈值、天数、奖励和资格语义不得重算或改写。展示函数是纯渲染，所以完整规则页、详情页，以及截止/开奖时对公告卡的编辑，会自然采用本稿明确列出的新文案（术语、时间、标点、图标），这是允许的。测试分别断言"规则事实不变"和"新文案正确"，不要求历史文本逐字不变。已经发出的消息不批量回溯编辑。
3. **同一概念只保留一个渲染函数。** 公告卡、完整规则页、创建摘要中相同概念的文案，必须来自同一个函数，不能各写一份。
4. **验证方式。** 每一项都要有对应的单元测试（文本断言）。涉及数据库的用例经 `bash deploy/run-shanghai-tests.sh` 运行；全部完成后跑 `ruff format --check`、`ruff check`、`python scripts/check_code_metrics.py` 和完整回归。不得在生产环境验证。
5. **测试更新。** 测试里旧文案的断言随本稿更新；回调身份断言不能随意放宽。

### P0-1 发言门槛按模式分别说明（公告卡 + 完整规则页 + 创建摘要）

**现状与根因**

- 已用测试夹具复现：本期累计模式下，"本期累计有效发言满 66 条"后面紧跟"按自然日统计"；固定日期模式下写"连续 3 天"，但没有说明是哪三天。

**合同依据**：[固定任务日期合同](fixed-message-task-calendar-20261029.md)"合同"节；计算逻辑见 `domain/message_calendar.py:16-19`（每个任务日分别达标，且天数等于窗口覆盖的自然日数），普通每日模式见 `domain/base_activity.py:15-28`（连续天数中断后重新计算，历史最佳连续天数达到 D 即合格）。

**目标文案**（N 为条数，D 为天数，日期一律按北京时间）

| 模式 | 判定条件 | 群行（公告卡与完整规则共用） | 模式说明（同一模式只出现一次） |
| --- | --- | --- | --- |
| 本期累计 | `count_mode == "period"` | `本期累计有效发言满 N 条` | `本期累计：报名通过后至截止前累计达标即可，各群分别计算。` |
| 普通每日，D=1 | `daily` 且未启用固定日期，D=1 | `任意 1 天有效发言满 N 条` | `每日门槛：按北京时间自然日计（0 点换日），各群分别达标；完成完整周期后，本群门槛无需重做，参与开奖仍须满足全部参与条件。` |
| 普通每日，D>1 | `daily` 且未启用固定日期，D>1 | `连续 D 天，每天有效发言满 N 条` | 同上，再加：`中断后连续天数重新计算。` |
| 固定任务日期 | `rules.message_task_calendar` 不为空 | `10月29日、30日、31日每天各满 N 条`；超过 4 天时写 `10月29日至11月5日共 8 天，每天各满 N 条` | `固定任务日：每个指定日期分别达标，多发不能抵其他日期，未来日期不能提前完成。本期任务时间：{开始} 至 {截止}。` |

### P1-1 修改未发布草稿中已有的奖品

**范围**：只针对未发布草稿，不涉及已发布活动。
**现状**：`telegram/creator_sections.py:134-154` 只有新增、删除、清空；`creator_prizes.py` 里的"重新输入名称"只服务于还没完成的新增奖品。
**目标**：
