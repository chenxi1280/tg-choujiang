# V3.2 创建与管理端按钮清单

- 日期：2026-10-06（北京时间）。状态：**R2 整合完成、待评审、未实施**。
- 配套主文档：[首页、按钮、排版与操作逻辑 PRD](v3.2-navigation-and-interaction-prd-20261006.md)。本附录只盘点创建、管理、群准备与隔离运维入口；成员和全局入口详见[成员按钮清单](v3.2-member-button-inventory-20261006.md)，通用控件、排版、反馈和编辑边界遵循同版[控件与体验合同](v3.2-controls-and-experience-contract-20261006.md)。
- 证据基线：当前工作区源码，包含既有未提交及并行修改；源码存在不等于当前生产已部署。未运行后端测试、数据库查询、发布、真实报名、取消或开奖。
- 下表 `draft_*`、`draft_gate:*` 等是服务端 action，创建器通常将其封装为 `secure:<token>`；管理动作同样使用授权 token。`nav:*` 是直接 callback；Telegram URL 是外链。动态参数用 `{chat_id}`、`{field}`、`{page}` 表示，不是待实现的字面值。
- 一行「A / B」表示现有键盘同一行两个按钮；分号表示不同行。目标页面和目标返回是 V3.2 设计，尚未写入业务代码。沿用已有 action 并不意味着可跳过授权、身份、草稿版本、状态或幂等检查。

## 1. 目标页面及主布局对照

| 页面 | V3.2 名称 | 目标上级 / 返回 |

| G02 / G03 | 使用指南 / 个人设置 | G01 |

| C04 / C05 | 参与群 / 开奖时间 | 实际来源页 / C01 |

| C07 / C08 / C09 | 额外关注/加入要求 / 用户限制 / 抽奖门槛 | C06；子编辑回对应列表 |
| C10 | 加成设置 | C01 |
| C11 / C12 / C13 | 每日发言加成 / 邀请加成 / 有效邀请要求 | C10 / C10 / 实际来源 C09 或 C12 |

| C17 / C18 | 我发起的抽奖 / 活动管理 | G01 / C17 的原范围、分类、筛选、页码与排序；C17任何状态均提供创建新抽奖 |

首页普通状态为五个控件：第1行「我参加的抽奖 / 我发起的抽奖」；第2行无草稿为「创建抽奖」、有效未发布草稿为「继续创建抽奖」、已经存在 `published_campaign_id` 为「查看发布状态」，分别进入新 C01、恢复原 C01、恢复同活动 C18；第3行「使用指南 / 个人设置」。同一位置只显示一个适用入口，不因回执失败二次建场。C17任何状态均有独立「创建新抽奖」，已有发布场不必取消；存在未发布稿时先选继续或明确确认替换。新稿身份与旧活动恢复记录分开，恢复记录按活动级持久保存，旧发布面板绑定原活动，不被新稿单会话覆盖。`/new` 沿用首页三种状态的恢复合同；主动另建通过C17入口。清空并新建只处理未发布稿，迁入 C15 确认页，不能当作取消旧活动。

C01 普通状态共十个控件：第1行「活动标题 / 奖品与领奖」；第2行「参与群 / 开奖时间」；第3行「参与条件 / 加成设置」；第4行「封面与说明 / 更多设置」；第5行按缺项显示下一步操作，齐全时为「预览并发布」；第6行「返回首页（草稿保留）」。下一步依「参与群→活动标题→奖品→抽奖门槛→开奖时间→最终预览」定位首个缺项，使用「选择参与群」「填写活动标题」「添加奖品」「设置抽奖门槛」「设置开奖时间」等真实CTA并直接进入对应模块；其他字段仍可自由编辑，不强制分步向导。十/五控件是普通布局，长内容分页、未完成恢复或状态操作可增加必要按钮，不能为保持计数删能力；返回首页不是把全部未保存内容一并提交。普通配置行至多两个控件；页码写正文，刷新另有明确标签，数值控件写单位和保存范围，开关正文显示当前状态。

- **当前源码事实与目标合同不同：** C18 当前只通过活动主群/兼容锚点实时 Telegram 管理员核验，非仅检查 created_by，见 [admin_flow.py:291](../../src/tg_lottery/telegram/admin_flow.py#L291)、[admin_authorization.py:6](../../src/tg_lottery/telegram/admin_authorization.py#L6)。这不是应沿用的多群授权政策；[V2.1 §3.1](v2.1-multi-group-participation-design.md#31-选择参与群)和[V2.2 §3.3](v2.2-configurable-participation-bonus-prd.md#33-权限矩阵)要求全参与群管理员交集。V3.2 目标对敏感详情、参与者资料及管理动作实时检查全部参与群；单群等价于唯一群。候选缓存和token不授予权限，仅管理主群不应管理共同活动。
- 多群新场发布时逐目标核验创建者、Bot和功能权限，邀请需邀请权限、发言需普通成员可发言，见 [creator_publication.py:124](../../src/tg_lottery/telegram/creator_publication.py#L124)、[creator_bonus_permissions.py:29](../../src/tg_lottery/telegram/creator_bonus_permissions.py#L29)。本版只整理反馈，不新增所有共同管理员必须批准之类业务限制。
- 现有送达汇总同时展示confirmed/pending/failed/unknown；V3.2 按规则页、主卡、群结果、中奖私信分别展示证据，不用健康状态或开奖回执替代远端送达。
