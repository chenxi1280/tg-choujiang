# V2.5 抽奖体验修复与新增需求验收

状态：本地代码与 369 项自动化回归完成，三个测试频道已创建；正式发布与线上业务验收进行中。

日期：2026-09-05。范围：当前 V2.3 多活动与逐群加成合同上的体验修复。

## 用户场景与行为

1. 参与、邀请与加成页用活动名称、开奖时间与列表序号区分活动，不展示随机活动短码；按钮内部仍按原公共引用绑定。首页提供“创建抽奖 / 我参加的抽奖 / 我的邀请记录 / 使用指南”；技术 ID 只在主动查询本人 ID 时出现，不占据默认操作路径。
2. 创建器、群列表、规则页、失败提示以群/频道名称展示；无法取得名称时明确“名称待更新”，不能把原始数字 ID 冒充名称。
3. 参与条件允许多个群聊及多个频道，必须全部满足；群聊用“加入”，频道用“关注”。加入申请尚未批准、核验失败和发言门槛不足分别解释。
4. 报名发言门槛与可选发言加成分开展示。门槛为至少 N 条；逐群加成按该群冻结的门槛、奖励、上限展示，不读取旧全局默认规则。
5. 每场抽奖、每个邀请人、每个群拥有独立邀请入口；抽奖截止只停止本期计奖，已生成的新版本入口继续可入群，永远不计入下次抽奖。历史 Telegram 链接若有真实过期时间则如实说明。
6. 邀请落地页显示具体计奖截止时间与抽奖时间；截止/开奖后不再显示“报名本次抽奖”，改为查看记录；无法核验、入口撤销不能伪装可用。
7. 内置指南覆盖创建、权限、全部加入后验证、逐群加成、截止后链接与领奖；支持配置自有使用说明频道、抽奖导航、精选推荐入口。未提供自有频道时保留内置指南，不把竞争对手频道当自有入口。
8. 后台指定中奖沿用现有隔离 ops Bot 与审计，正式 Bot 不展示操作入口；中奖仍参加正常冻结、资格与通知流程。本轮用户已明确：后台指定，前台正常展示中奖结果，不隐藏中奖者。
9. 所有个人中心回调必须按点击者查询，不能使用机器人自己发出的消息的 from_user 作为业务用户。

## 额外修复

- 旧版底层 Telegram 邀请链接已过期时，允许生成下一版本，稳定外发入口不变。截止后仍不允许新增本期加成入口。
- 发布失败页显示群名与中文处理提示，完整 Telegram 错误继续保存在 Outbox，远端结果未知仍明确显示，不当作可安全重试。
- 逐群加成设置复制页显示实际奖励次数，避免把非 1 次奖励写成 +1。

- 逐群发言加成只校验启用该规则的群，额外准入群仅要求加入时允许其保持只读；历史全局发言规则继续按原合同校验。

## 深度对标补充（2026-09-05）

- 组合分享链接：在准入条件下设置/清除 Telegram addlist 链接，随本场展示快照冻结；公开卡提供一键加入按钮。链接本身不决定资格，参与群、频道、地区、用户名和发言门槛依然逐项核验。禁止把任意网站或普通邀请 URL 误标为组合加入。
- 指定奖品删除：原来只能删最后一个，改为按名称和自然序号选择删除，可一次删除多项；剩余奖品保持顺序。打开已有奖品配置时也能直接找到删除入口。
- 发布错误涵盖私有条件入口生成和活动卡发送两个阶段，以群/频道名称解释。仅对 Telegram 明确未接收的失败项重试；未知结果不重放。过截止时间禁止恢复发布，管理员需取消旧活动后新建。
- 私有准入链接成功投影幂等，重复接力不得生成第二张同群活动卡。历史链接成功但未投放的过期测试活动应通过正常取消服务关闭，保留原失败历史。
- 对标证据从公开页扩展到真实私聊菜单及输入错误：满人开奖 0 被目标拒绝并提示当前账号 1–300；目标说明 30 天中午自动开奖。客户等级、永久人品积分与排行、导航推送规则单列，不与本场邀请奖励混同。

- 后台控制台：通过服务器 SSH 和 OPS_ADMIN_IDS 白名单访问，共用指定服务，审计来源区分 offline_ops_cli 与隔离 Bot；不在前台注册命令或启动另一份正式 Bot polling。测试需要覆盖白名单、设置/撤销、审计与正常开奖展示。
