## 4. 本轮修复的文档遗漏与保护边界

- 明确保留“分享活动”“获取分享卡片”“分享到群或频道”“复制/打开/转发个人邀请”的入口，前者宣传与后者归因分开。
- 分享卡/原公告适用的邀请、我的加成、群文件夹按钮保留；不能为只留一个主按钮悄悄撤掉辅助项。
- 新按钮列数要求不适用于已有减/值/加数字三联控件，也不把确认删除与保存等不同语义按钮打散混排。
- 原未报名提示的首次触发/冷却/去重不因消息被删重置；开启默认删除不改变提醒产生条件。
- 创建器的草稿24小时有效期、封面上传/替换/完成/清除、群选择搜索分页、返回和保存、复制与旧面板保护全部保留；本稿不是重做创建器功能。
- 两官方频道与启动Bot的冻结策略、各群门槛、每日/累计加成、邀请24小时留存及同群同人一次、各版上限、最终资格复核、不可变开奖快照保持。
- 开奖群公告、中奖私信、创建者通知分别投递，关闭扩展提示不关必要结果通知；用户ID提及、北京时间与同场结果入口保留。
- 活动暂停/截止后停止无效任务引导，既有窗口内的邀请待核验事实继续按原规则处理；无自动补发历史UNKNOWN。

对应产品条款在 R14 PRD 补齐并关联新验收项；本轮没有以“修复”名义执行这些代码变更。

## 5. 实施前的核对顺序

先核对第3节改变旧行为的项目，尤其C02/04/07，C03只核对展示与原流程是否保持；其后按第2节落实代码差距。原有分享与进度属于回归保护，不需要重写整套。任何代码阶段的验证需使用上海专用测试执行器；真实新用户、群/频道选择器和公开转发的业务结果另行验收。本轮没有运行这些验证，不报告通过。

## 6. R14 再审结果（2026-10-30）

本次只修订文档：撤回没有明确需求依据的自动置顶；消除竞品表与公共列表的个人信息冲突；补齐个人进度翻页身份、匿名发言和话题边界；明确错误消息删除优先级与删除在途竞争；补齐首次开始意图与状态一致持久化、暂停恢复/改期去重、待确认发布及发送前状态核对；修正人数、邀请模块和秒级时间示例。对应主PRD §10.3、AC51及AC53～AC56。

复查当前 `_campaign_start` 仍仅转换状态，且running直接返回，不能把新增开始卡当成已经实现。此次发现的是设计缺口与待实施约束，并未验证或判定某场生产活动的实际通知结果。其他表格中的源码实现结论保留此前核对日期，不视为本轮全仓重新验收。
