# V2.0 LotteryBestBot 对齐版 · 交互层重构设计

日期：2026-08-15
状态：待用户审阅
前置研究：@LotteryBestBot 全流程研究（t.me/lotterynav 消息 59/161/252/422/935/2811 及数百个抽奖帖样本）；现有代码实现审计（188 项测试通过）。

## 0. 背景与问题诊断

用户在实际使用中反馈多项功能"缺失"。经代码审计与 git 历史核查：

1. **生产版本疑旧**：`/region`、`/myid`、"抽奖加成"键盘配置等在当前 master 均已实现，git 历史从未出现用户所述"人情加成"文案，生产环境极可能运行旧代码。完成后需统一重新部署并核对 SHA。
2. **可发现性差**：命令均为私聊命令且未注册 `set_my_commands`，用户在群内发送无响应，产生"没有该功能"的观感。
3. **真实交互差距**（本次重构核心）：
   - 群内抽奖帖"立即报名"是 URL 深链跳私聊；LotteryBestBot 为群内直接点按钮、当场校验、弹窗反馈。
   - 帖子样式未对齐 LotteryBestBot 经典格式（参与条件逐行列出、含群链接与发言门槛）。
   - 缺少"发言数 ≥ N 条"硬性参与门槛（LotteryBestBot 参与条件支持逐群设置）。
   - 缺少 `/getid` 群内命令。

## 1. 目标与非目标

**目标**
- G1 群内点按钮直接参与，无需跳私聊；当场资格校验 + 弹窗反馈。
- G2 抽奖帖完全对齐 LotteryBestBot 格式，参与条件（含链接、发言门槛）一眼看全。
- G3 参与条件支持逐群设置"发言数 ≥ N 条"硬性门槛；有效发言 = 去除空白/emoji 后 >3 字的文本消息，相同内容刷屏去重。
- G4 命令可发现性：注册命令菜单、群内命令引导、新增 `/getid`。
- G5 发布后自动置顶（无权限降级跳过）。
- G6 生产部署与 master 对齐。

**非目标**
- 不重写领域层（账本、快照、开奖算法、邀请生命周期、资格复核全部保留）。
- 不实现 LotteryBestBot 的"人品积分账户/排行/管理员加减分"体系——本项目以"本期抽奖加成"（邀请阶梯 + 每日发言）替代，此差异为既定产品决策。
- 不做导航频道发布、客户等级（维持 TBD）。

## 2. 用户已确认的关键决策

| 决策点 | 结论 |
|---|---|
| 群内参与方式 | 群内直接点按钮参与，当场校验弹窗；需要邀请链接等管理功能时才跳私聊 |
| 发言数角色 | 双角色：既可作硬性参与门槛（逐群设置），也可开每日发言加成（软性奖励） |
| 帖子样式 | 完全对齐 LotteryBestBot 格式 |
| 有效发言 | >3 字文本计 1 条；纯表情/贴纸/图片/命令不计；同用户同群连续相同内容去重 |
| 创建流程 | 保持：点"创建抽奖"直接进预览面板逐项设置 |
| 参与条件数量 | 1–3 个群/频道，不设死限制；支持直接发送链接添加 |
| 邀请加成 | 保持现有阶梯模型（如 1人+1、2人+3，上限封顶），键盘配置 |
| 每日发言加成 | 保持：每日达标当日 +1 次，逐日独立结算，不要求连续 |

## 3. 命令与入口

| 命令/入口 | 位置 | 行为 | 状态 |
|---|---|---|---|
| `/start` | 私聊 | 欢迎语 + 主菜单（创建抽奖/我创建的/我参加的/归属地/我的ID/添加到群·频道） | 已有 |
| `/new` `/index` `/join` `/region` `/myid` | 私聊 | 现状保持（/region 34 省键盘；/myid 返回用户 ID） | 已有 |
| `/getid` | 群内 | 回复当前群 chat ID（含 -100 前缀说明），用于私有群配置 | 新增 |
| 私聊命令误发到群 | 群内 | bot 被点名（/region@bot 等）时回复"该命令请在私聊中使用"+ 深链按钮 | 新增 |
| 命令菜单 | 客户端 | 启动时 `set_my_commands`：私聊 scope（start/new/index/join/region/myid）+ 群 scope（getid） | 新增 |

## 4. 创建抽奖（保持骨架，两处增强）

入口：私聊 `/new` 或主菜单"发起抽奖活动" → 直接进入**预览面板**（成品文案为中心），逐项设置。

增强点：
1. **参与条件设置**：添加 1–3 个群/频道（发送链接/`@username`/私有链接均可，现有解析保留）；每个**群**条目新增可选步骤"🗣 发言数 ≥ N 条（参与门槛）"，N ∈ [1, 500]，默认跳过。频道无此选项。
2. **发奖人员**：默认创建者本人，可改为 `@username` 或数字 ID（消除"用户 ID 是什么"的困惑：默认无需填写）。

其余配置项（标题/封面/用户限制/奖品/说明/抽奖加成/开奖方式/消息提示）保持现状。

## 5. 群内抽奖帖（完全对齐 LotteryBestBot 格式）

```
🎰 **{标题}**

📮 **参与条件：**
🌏️ 归属地：广东               ← 设置限制时
🪪 必须设置用户名             ← 开启时
🎫 加入-[吃瓜群](https://t.me/...)
└ 🗣 发言数大于 **10** 条     ← 该群设门槛时
🎫 关注-[通知频道](https://t.me/...)

🎁 **奖品内容：**
💰️ 100元优惠券 × 5

⚠️ **抽奖说明：**
{创建者自定义文本}

🔋 **抽奖加成：** 邀请 1人+1次/2人+3次（上限5）｜每日发言满10条 +1次   ← 开启时

📅 **开奖日期：**（北京时间）
2026年08月20日 21时00分00秒
（或）🎊 **满人开奖：** 达到 30 人参与后立刻开奖
```

- 有封面时保留 `send_photo + caption` 路径，caption 用同格式。
- 键盘改为 **callback 按钮**：`[🎫 立即参与] join:<public_ref>`、`[🔋 获取加成链接] bonus:<public_ref>`、`[📜 规则] rules:<public_ref>`（callback_data ≤64 字节，public_ref 为短随机串，满足）。
- 发布 Outbox 成功后追加 `pin_message`（`disable_notification=true`）；失败降级仅记录，不阻断。

## 6. 群内直接参与（核心新流程）

用户在群内帖子上点 `🎫 立即参与`：

1. `update_handler` 路由群消息 callback（`join:<public_ref>`）→ `member_flow` 新处理函数。
2. 当场校验（bot 为管理员，`getChatMember` 逐条件群并发查询）：
   a. 活动状态（进行中/未截止）；
   b. 用户名必填（开启时）；
   c. 归属地限制（开启时）；
   d. 全部条件群/频道成员资格；
   e. 逐群发言门槛（查累计有效发言数，见 §7）。
3. 反馈（`answerCallbackQuery(show_alert=True)`，文案 ≤200 字符）：
   - 全部通过 → "✅ 参与成功！当前共 N 次抽奖机会"（N = 1 + 已获加成）；
   - 未加群 → "请先加入：{未达标群名列表}"（帖子内已有链接）；
   - 归属地未设/不符 → "请先设置归属地（{省份}）"；
   - 发言不足 → "{群名} 发言 3/10 条，还差 7 条"；
   - 已参与 → "你已参与，当前 N 次机会"。
   - 多项不达标时弹窗列前 2 项 + 群内回复详细清单（沿用现有延迟删除策略）。
4. 与现有私聊报名链路**并存**：私聊深链 `/start join_<ref>` 保留，两条入口收敛到同一 `begin_registration → observe_memberships → complete_registration` 服务（复用现有资格复核与审计）。
5. `🔋 获取加成链接`：
   - 未报名 → 弹窗"请先参与本次抽奖"；
   - 已报名且开启邀请加成 → 若用户 /start 过 bot，私聊发送专属邀请链接（密文存储、解密下发，现有逻辑）；否则弹窗 + 深链 `?start=invite_<ref>` 引导进私聊一次。
   - 未开启邀请加成 → 弹窗"本期未开启邀请加成"。

**技术约束**：群内 callback 不要求用户先 /start（answerCallbackQuery 可直接回复）；私聊推送必须用户 /start 过，故邀请链接走深链引导。弹窗 200 字符上限内精简文案。

## 7. 发言统计与门槛

**数据模型**（新增迁移）：
- 新表 `user_group_message_totals`：`(user_id, chat_id)` 主键，`total_count`、`last_digest`（最近一条有效消息内容哈希，防连发去重）、`last_message_at`。累计计数，服务门槛校验。
- `campaign_required_chats`（现有冻结表）新增列 `message_threshold INT NULL`（仅群类型使用；发布时随冻结快照落库，开奖复核用同一冻结值）。

**有效发言规则**（门槛与每日加成统一口径）：
- 仅 `text`/`caption` 非空消息；去除空白与 emoji 后字符数 >3；
- 贴纸/图片（无 caption）/动画/命令（`/` 开头）/机器人消息不计；
- 同用户同群与上一条有效消息内容相同 → 不计（`last_digest` 比对）。

**计数路径**：polling 收到群消息 → 过滤 → upsert `user_group_message_totals`（+1）→ 现有 `DailyProgress` 每日进度同步应用同一过滤（`activity.py` 现有 valid 计数逻辑对齐上述规则）。

**校验时点**：报名时（§6.2.e）；开奖前 `qualification_review` 复核（现有 Job 扩展：门槛群逐人复核累计数，不足者标记不合格）。

## 8. 开奖与结果（微调）

- 群公告文案对齐："🏆 {标题} 开奖结果"+ 逐顺位中奖者 + 未分配名额（现有逻辑，微调文案）。
- 开奖后**编辑原抽奖帖**：状态行追加"已开奖"+ 中奖者名单（复用现有 `add_campaign_card_state`，确认编辑内容包含结果文本；帖子过长则仅置顶结果公告）。
- 中奖私聊通知、领奖登记保持现状。

## 9. 邀请链接机制（保持，入口前移）

- 每人每期唯一、密文存储、自邀拒绝、留存校验、过期保留链接仅停归因——全部保留。
- 入口从"私聊报名成功面板"前移到**群内帖子按钮**（§6.5）。

## 10. 部署与验证

1. 合并后走 `deploy/release.sh` 全量发布；发布后核对生产 SHA = master HEAD。
2. 真机 E2E 验收（此前一直 unproven，本次列为必做）：
   - 私聊创建 → 预览逐项配置（含逐群发言门槛）→ 发布 → 群内帖子样式与置顶核对；
   - 群内未加群用户点参与 → 弹窗引导 → 加群 → 再点 → 成功；
   - 发言不足 → 补发消息 → 门槛通过；
   - 获取邀请链接 → 新用户经链接入群 → 加成到账；
   - 次日发言达标 → 每日加成 +1；
   - 开奖 → 群公告 + 中奖私聊 + 原帖编辑状态；
   - 截止后邀请链接仍可入群、不计加成。

## 11. 测试策略

- 单元：有效发言过滤矩阵（长度/类型/去重/命令）；门槛校验边界；callback 路由（群/私聊）；帖子文案快照（含条件分支组合）；pin 降级。
- 集成：群内参与全链路（fake gateway 模拟 callback + getChatMember）；双入口（群内/私聊）收敛一致；资格复核扩展。

## 12. 风险与边界

| 风险 | 缓解 |
|---|---|
| Bot API 无法获取 bot 入群前历史消息，发言累计从 bot 在群期间起算 | 产品口径同 LotteryBestBot（均只能统计 bot 可见消息）；帖子和创建器文案注明 |
| 群内 callback 事件要求 privacy 关闭或 bot 为管理员 | 发帖前置校验已要求 bot 为管理员，天然满足 |
| 弹窗 200 字符限制 | 文案精简；多项不达标改群内回复详细清单（延迟删除） |
| 编辑原帖超长（中奖者多） | 超长仅置顶结果公告，原帖只改状态行 |
| 旧版生产代码 | §10 统一发布并核对 SHA |
