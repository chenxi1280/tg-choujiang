# 固定任务日期与已授权的天上人间活动修复

用户要求「【天上人间】一直抽奖（第一期）」只统计北京时间 2026-10-29 20:00
至原定 2026-10-31 19:55 的发言和加成；29、30、31 日每天各 36 条，20:00 开奖不变。
开始前的发言、加成与由其产生的门槛资格均不生效。基础报名次数及前置资格事实保留。

## 合同

- `message_task_calendar=campaign-days-v1` 显式启用固定任务日期，未启用的历史活动沿用原规则。
- 活动 `preheat_at`、`cutoff_at` 是本期统计边界；本人的登记通过时间仍是个人下界。
  各北京时间任务日必须分别达到设置条数，多发不能替代其他日期，未来日期不能提前完成。
- 门槛天数必须等于任务窗口覆盖的自然日数。已有活动没有此标记时不自动改变统计方式。
- 进度区分「今日任务已完成」「本期已完成 X/Y 天」和「整场门槛已完成」。
  发言加成仍独立计算，整场门槛未完成时基础次数与加成暂存。
- 新能力加入运行制品能力守卫；数据库存在此规则时，拒绝回滚到不支持该规则的镜像。

## 修复入口

部署新制品后，在其 app 容器中执行 `python -m tg_lottery.ops.reset_message_window`。
必须传入活动 ID、期望名称、唯一参与群、带时区的新开始时间、原截止与开奖时间及授权引用。
不传 `--expected-fingerprint` 时只预览；传入预览配置指纹后事务内重新核验并应用。
预览与应用之间的新增消息在锁内重新计算，不使用旧计数覆盖实时进度。

入口锁定活动、参与者、每日进度、达标与相关通知记录，拒绝已有开奖快照、活动身份漂移、
账本与缓存不一致、邀请加成混入或通知仍在执行的情况。此入口只支持最后任务日之前的
进行中活动；不会修改其他活动，也不会触发开奖。

原始消息不删除；开始前已接受事件标记为 `before_task_window`，对外消息计数也不再包含它们。
窗口内去重从新起点重新判定，仅更正需要改变的有效性标记，旧值存入审计。
历史加成账本不删除或改写，以同类型有符号更正分录调整每日加成与缓存。开始前的每日计数
归零，但保留旧记录。错误达标记录置为未达标，后续真实完成可在同一记录上恢复达标。
更正后的新加成采用新 revision 的幂等键，避免与已冲回的旧奖励键冲突。

应用保存 `campaign.message_window_reset` 审计、最小更正前快照与新的冻结规则修订。
重复执行同一授权引用返回 `already_applied`，不重复扣减。
尚未执行的旧进度通知取消；已确认和 UNKNOWN 投递的历史事实保留，不自动重发。
应用后以新事务独立核对任务时间、逐日消息、门槛、每日奖励、账本与缓存和同场进度文本。

## 评审与验证重点

- 正确性：20:00 开始边界、自然日、未来日期、缺一天、多发不抵次日、旧资格撤销后重新完成。
- 性能：按活动锁隔离重算；本场事件一次按序读取，逐用户/群/日聚合，不全库扫描消息。
- 可维护性：固定日期显式版本化，原合同默认不变，统计、进度与正式修复入口共享规则。
- 安全性：精确身份、配置指纹、锁、事务、审计与重复执行保护；保留未知投递和原账本。
