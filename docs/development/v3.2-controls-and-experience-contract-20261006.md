## 1. 控件的一次点击究竟做什么

每个控件必须同时定义：当前活动/用户/群、显示条件、点击效果、保存范围、结果反馈、返回目标。正文给条件和真实状态，键盘给可执行动作，不能让“查看”“复制”“保存”“提交”“恢复”共用含糊成功文案。

| 事实 | 允许的反馈 | 不得推断 |
|---|---|---|
| 本人查看/翻页/打开群 | 页面已更新或打开已有入口 | 自动登记、已完成门槛、已计邀请 |
| 参数保存到草稿 | 已保存哪个字段/群/整场门槛 | 已发布或历史活动规则已改变 |
| 本人确认登记 | 同场本人已登记及条件核验状态 | 已最终合格或已有基础次数，除非已有相应事实 |
| 发布/链接/分享进入处理 | 已提交，处理中或待核查 | Telegram已经接受/用户已经收到 |
| 复制、用户选择转发或打开联系人 | 提供原生复制/转发/打开能力 | Bot已代用户发送、对方收到、邀请有效、奖品已领取 |
| 账本/门槛更新与开奖结果 | 相应业务事实及其时间/身份 | 群通知/中奖私信已送达或客户端声音已响 |

控件服务继续使用授权 token/现有会话；不能把完整上下文塞成超长 callback。所有个人入口绑定点击本人，敏感管理及动作按全参与群实时管理员交集核验，缓存列表不是授权。旧写入按钮只恢复当前同身份页面，不执行旧动作。

群内个人详情、完整账本、邀请明细/链接及领奖联系模板查询只投递点击者本人私聊，私聊不可达明确反馈；这不关闭V3.0 §6的本群必要达标/奖励通知。群通知仍按合同提及本人、展示本群事件及适用次数/资格摘要，不扩散跨群完整账本、邀请明细或个人邀请链接。

## 2. UC 控件规范

| 编号 / 类型 | 标签与确定行为 | 单位 / 保存 / 返回 |
|---|---|---|
| UC01 导航 | 动词和对象明确，如“查看参与条件”“返回活动”；组合入口先摘要页，不直接开启输入 | 不写业务；携带origin、活动、群、分类、筛选、页码；返回真实来源 |
| UC02 主操作 | 每页突出当前下一步，独占一行；缺项按钮写具体字段，完整后才“预览并发布” | 指导但不锁其他入口；首次登记、正式发布、开奖分别用明确提交动作 |
| UC03 开关 | 显示“当前开启/关闭”和作用范围；本模块、本群、扩展说明分别命名 | 即时开关只改声明范围，刷新留本页；关闭保存参数可恢复，不串改其他模块 |
| UC04 单选 | 当前值用勾选及正文表达；门槛发言/邀请唯一选中，选项说明不同后果 | 模式先进入编辑稿，保存明确替换；不默设类型、不增加无门槛模式 |
| UC05 多选 | 每项有自然序号、完整正文身份、选中状态；列表按钮点击切换该项 | C04/C07选择即时保存并反馈；复制目标选择只暂存，不能混作已覆盖 |
| UC06 数值与预设 | 字段标题含单位；数值行“−1 / 当前值·自定义 / +1”，预设含单位并标选中 | 人、条、天、次/轮分清；预设替换当前字段，不提交整个规则、不覆盖其他值 |
| UC07 搜索/清除 | “搜索群/频道/活动”，显示关键词、匹配数及无匹配；“清除搜索”恢复未筛选列表 | 搜索不改选中/规则；筛选从有效首页面开始；取消输入回原列表 |
| UC08 分页 | 正文显示当前/总页、总数；仅有可到达方向才生成上一页/下一页，页码本身不伪装动作 | 不写业务；越界回有效页并提示列表变化；排序变化按稳定活动/群/记录身份定位 |
| UC09 保存/暂存 | 单字段即时保存、本群设置保存、本群门槛暂存、整场门槛保存各用具体标签 | 只写对应范围；“返回首页（草稿保留）”不是全场提交 |
| UC10 取消/放弃 | “取消输入”只取消字段；“放弃本群修改/放弃本场门槛修改”丢对应编辑稿 | 其他待编辑值保留；跨命令/深链离开终止字段接收，保留目的地，再处理对应稿 |
| UC11 危险确认 | 清空/载入覆盖/移除关联群/取消活动/截止/开奖/登记领奖列身份和后果，确认独占行 | 确认绑定原版本及范围；执行重验状态/权限；取消回原页，重复提交不重复写入 |
| UC12 复制/转发 | “复制我的邀请链接”“转发邀请”“复制领奖联系信息”各复制/分享对应真实数据 | 仅本人剪贴板或由本人选择转发；不自动发消息，不凭点击计奖/登记/领取 |
| UC13 刷新/处理状态 | 先回应callback结束客户端等待，这不是业务成功；“刷新状态/重新检测”只查询或原核验；长动作显示处理中与已有事实 | 刷新不暗中补发/生成/重算；UNKNOWN无盲重试，明确失败才走既有人工窄重试；不给无依据的完成时间承诺 |
| UC14 错误/空态 | 写明具体对象、原因、仍可完成的操作；提供正确修复入口、重新检测和返回 | 不假装成功，不跳过必需群，不自动放宽；没有规则/活动/权限/结果是不同空态 |
| UC15 图片 | 上传/替换仅在封面输入页接收；成功生成新的当前确认面板，可连续替换 | 单次只改封面；完成回C14；清除不删说明/其他稿；离开后不误收图片 |
| UC16 链接 | 群、个人邀请、报名、宣传、联系人按用途显示；链接可用性依据真实事实 | 普通加入不归因，个人邀请按本场本人本群归因；URL不能代替业务状态 |
| UC17 记录筛选 | 状态筛选标当前选择，未知单列，不与无效/失败混同 | 分类/筛选/分页只读；返回保留原位置，不自动切最近活动 |
| UC18 达标/结果反馈 | 活动、群、事件日期、当前资格、入账/暂存/有效次数按真实事实显示 | 同来源可合并通知，业务事实分别幂等；结果以完成DrawRun/快照/取消审计为依据 |

普通操作行最多两项；同一数值的减/当前/加可三项，预设和筛选按字段成组。按钮不可只靠emoji或颜色传意。不可用动作正文说明原因，仅展示可用恢复动作；本版不生成无效callback假禁用，也不依赖尚未核验的SDK/客户端新特性。

## 3. 页面模板与身份辨认

| 模板 | 固定正文顺序 | 底部操作顺序 |
|---|---|---|
| PT01 首页/角色列表 | 页面名→本人角色任务→草稿/发布恢复状态或分类统计→列表与页码 | 主要任务→分类/分页→其他角色范围/新建→首页 |
| PT02 草稿模块摘要 | 草稿标题/未发布→真实缺项与下一项→已保存值→未保存编辑值及保存方式 | 具体子操作→辅助复制/移除→保存/放弃→原上级 |
| PT03 规则群编辑 | 活动及群身份→门槛或奖励类型→字段值/单位→改变后的规则句→保存范围 | 预设/数值→模式→保存/放弃→原群列表 |
| PT04 成员活动详情 | 活动状态→完整条件/本人登记→本人进度与次数→差项/下一步→截止/开奖/奖品 | 登记或适用下一步→门槛/加成/邀请子入口→规则/宣传→来源列表/首页 |
| PT05 群任务/记录 | 同活动同群→真实规则与入口→今日/累计/本场完成事实→记录状态与页码 | 去本群/我的邀请链接→本群记录/刷新→origin返回 |
| PT06 发布/管理/结果 | 同活动身份→真实生命周期→逐目标投递/权限阻断→统计或结果→作用范围 | 当前可用操作→危险确认/适用领奖→状态刷新→来源 |

- 长活动名、群名、奖品名完整写在正文；按钮可采用“自然序号·名称”识别，内部ref不作主要文案。
- 同名同类型且无username的群，正文用完整名称+自然序号，必要时加chat ID尾号；业务操作绑定稳定Group/participation_group身份，调用Telegram时解析当前真实chat ID。标题、序号、username和尾号仅展示；群升级沿用原关系与新旧路由别名，旧按钮仍定位同群，不重建进度、邀请归因或奖励。
- 同名活动同时显示开奖时间及自然序号；翻页序号/排序变化不能改变已经绑定的活动身份。
- 群列表沿用每页6项、记录沿用原每页容量（现有邀请记录10条），这是传输布局，不是总量上限；活动/记录按完整范围服务端逐页查询，冻结群目标按完整manifest分页，不先limit20或全量加载记录到内存后伪分页。
- 超过21场的活动也必须可达；删除/终态变化导致旧页越界时回有效页并提示，不能显示伪空列表或丢原筛选。
- 超长条件/群配置按完整数据块分页，不截断条件、奖品或进度；每页有活动身份、规则版本、当前/总页和来源返回。

身份和分页继承[V2.3 通用按钮规则](v2.3-participant-button-record-interaction-contract.md#2-通用按钮规则)，导航及长文规格继承同版主PRD §9；修正旧查询截断不改变任何资格/抽奖数量。

## 4. 创建：下一项、组合页面与奖品两步

C01 推荐下一项顺序为参与群→标题→奖品→抽奖门槛→开奖时间→最终预览。跳过已完成项，顶部写“下一项：名称”；主CTA直接打开该项，按钮保留具体来源。可随时用其他控件调整，不强制按序填写，不因导航顺序新增资格限制。没有可管理群先进入群准备页，真实检测后继续。

| 当前必填状态 | C01主CTA | 点击/完成后的反馈 |
|---|---|---|
| 无参与群 | 选择参与群 | C04；无可管理群显示添加Bot/设管理员/重新检测；完成回来源 |
| 缺标题 | 设置活动标题 | C02输入；保存后回C01展示下一项 |
| 无完整奖品 | 添加奖品 | C03→名称→人数；半笔pending不是完整奖品 |
| 缺完整行为门槛 | 设置抽奖门槛 | 直接C09，注明属参与条件；选择类型/群并保存整场后回来源 |
| 缺时间或时间需要调整 | 设置/调整开奖时间 | C05；按强制门槛窗口校验，保留原值/明确错误 |
| 必填完整 | 预览并发布 | C16使用共享公告投影；先复核，再由本人确认提交 |

组合入口的点击只打开摘要页：

| 页面 | 正文 | 具体子操作与返回 |
|---|---|---|
| C03奖品与领奖 | 已保存奖品列表、人数及完整当前领奖说明 | 添加奖品；有奖品时删除指定奖品/清空奖品；领奖说明；返回草稿。不新增单项奖品编辑 |
| C14封面与说明 | 封面当前状态/可展示图片、说明摘要与完整查看 | 上传/替换封面、抽奖说明、有封面时清除、返回草稿。点具体字段才接收对应媒体/文本 |

| 奖品新增步骤 | 字段/单位与按钮 | 确定保存/取消结果 |
|---|---|---|
| 名称 | 奖品名称；取消新增奖品 | 有效名称只写pending，不追加清单；取消只丢本次pending并回C03 |
| 人数 | 中奖人数：人；重新输入名称/取消新增奖品 | 明示名称已输入但尚未加入清单；非法人数保留名称，留人数页 |
| 重新输入名称 | 显示本次pending名称 | 返回名称步骤供修改，不改已保存奖品；改名后回人数步骤 |
| 有效人数提交 | 按原正整数校验 | 同次新增原子追加完整奖品并清pending；重复来源不重复追加，不改变其他奖品顺位 |
| 跨模块离开/恢复 | 终止字段接收，保留本次pending及目的地 | 回来继续人数步骤；取消新增与取消单字段不同，不能把半笔pending当完整保存 |

即时保存字段与编辑稿必须在页首写明。参与群/额外条件选择即时保存；门槛两层标签为“本群暂存到编辑稿”“保存本场门槛”。取消数字输入保留其他值；删群同时列已保存和未保存影响并原子清群引用/复制选择，其他群值保留。

封面连续替换每次确认都绑定新的当前面板，旧按钮只提供恢复当前稿；完成回C14；清除只清图片，正文说明和其他设置保留。离开封面页终止图片接收，后续图片不覆盖原封面。

## 5. 两类加成、数值、预设与复制

| 字段 | 明确单位/规则句 | 保存及独立性 |
|---|---|---|
| 发言门槛 | 每日N条、连续D天；本场完成一次即可 | 属门槛，不增加抽奖次数；无最低字数控件 |
| 邀请门槛 | 本群已确认有效新成员K人 | K是资格阈值，不是邀请累计上限 |
| 每日发言加成 | 每轮N条、每轮增加R次；每天一次/每日最多C轮/每日不限 | 每日最多奖励C×R次与轮数分开；北京时间自然日，历史奖励保留 |
| 邀请加成 | 每X个已确认有效新成员增加1次，本场累计不限 | 不显示新场累计上限字段；留存与门槛共享 |
| 有效邀请要求 | 立即核验或留存H小时；截止/最晚入群/开奖三时点 | 门槛来源随外层稿保存；加成来源即时保存；未改快照跟基线，双显式修改先解决冲突 |

2026-10-06 创建体验修订：新配置的群发言门槛和每日发言加成统一提供 **5、10、20 条、自定义**；新建本群规则的初始条数为5。自定义仍接受正整数，包括2、34等；已保存草稿、复用来源和历史活动保留本人原值。门槛只改每日条数，加成只改每轮条数，连续天数、奖励次数和每日轮数保持独立。

预设必须紧跟对应字段并带单位；点击只替换该字段，不自动保存群/整场。不设上限↔有限切换保留本人最后输入的独立上限；数量变化不能覆盖它。有限模式缺值明确报错留页，不填假大数代表无限。

| 本模块状态 | 本群保存按钮 | 保存前后必须说明 |
|---|---|---|
| 已开启 | 保存本群设置 | 只写本群规则，保持模块开启，其他群原值不变 |
| 已关闭 | 保存并开启本加成 | 列出将同时恢复的全部已配置群及规则，包括本次群；保存后模块开启与群数可读，另一类加成/门槛不变 |
| 放弃修改 | 放弃本群修改 | 保留原参数和原模块开关，不能借取消启用或关闭模块 |

加成复制来源必须是已保存完整规则；未保存先明确去保存或继续编辑，不复制隐含working copy。门槛复制只进入外层门槛编辑稿，整场保存之前不生效；两种复制页首分别说明。

复制选择页使用“全选本页”“清空已选目标”，后者跨页仅清复制目标，不清业务规则；逐项说明当前关闭/将覆盖。确认页列来源规则、全部目标及将覆盖字段；确认只改同类模块。零目标不写任何群，取消回来源群并保留其他编辑值。

## 6. 首页、多活动与持久发布恢复

G01主要控件无稿“创建抽奖”、有效未发布稿“继续创建抽奖”、已有活动身份“查看发布状态”。创建结果未知先查原幂等来源，恢复同活动阶段，不把会话缺字段当未创建。原发布/投递/Attempt身份不能被新草稿覆盖。

C17始终有“创建新抽奖”；不要求先取消/结束旧场，包括未知原场。已有未发布单稿时按继续或明确替换确认处理；已有发布场时先保证原草稿幂等来源→活动身份、发布阶段和恢复路径已活动级持久绑定，再为独立新场生成新草稿身份。旧场恢复不能只依赖即将被新稿覆盖的单一会话；仍可从列表/原身份恢复，不覆盖、不重发、不隐式取消。这里保留现有多活动能力，不新增并行数量上限。

跨命令/深链离开编辑终止字段接收，保留待编辑值、原上下文和目的地；编辑稿提供保存对应稿/放弃对应稿/继续。验证失败留原页，不丢值；真实24小时过期明示，不将迟到文本/图片写入新稿，不承诺恢复已过期数据。

管理范围分“我发起”和“我可管理”，敏感详情/动作实时核验全部参与群管理员交集；缓存只候选。权限阻断与人工暂停分开，列故障群/缺失能力/真实恢复检测，修复不补造未知观察、不自动恢复人工暂停。失败/UNKNOWN处理按既有机制，不因控件统一增加自动重试。

PUBLISHING取消保留UNKNOWN、Attempt及对账事实；迟到确认不重开活动，确认卡按原投递路径更新取消。确认发生状态/权限变化，展示最新事实及可用操作，不能按旧按钮执行无效承诺。

## 7. 成员直达、发言、邀请、宣传与领奖

M02活动详情直接内嵌本人进度，展示成员条件、逐群行为门槛、基础/发言/邀请累计、暂存、当前有效次数；M04旧路由是该进度区域别名，不新加中间页面。门槛详情、加成明细、我的邀请链接/记录从M02直接可达。

只有一类规则或一个群可直接打开相应详情，但origin仍指实际来源；“返回”不能再次自动直达同页。其他模块关闭不能隐藏门槛进度；未登记先完整读条件再明确登记，查看/翻页/入群不自动报名。

发言群详情提供“去本群发言”，只使用该活动群真实已可用普通入口，不能拿本人归因邀请链接冒充普通加入。没有可确认入口时解释缺口、给真实条件检查/返回，不生成假链接；完成规则仍靠被观察并符合条件的真实消息。

| 邀请入口事实 | 本人看到的确定操作/反馈 |
|---|---|
| 尚未创建且功能/窗口适用 | 我的邀请链接；本人明确请求，显示本活动、本群和用途 |
| 已请求/生成中 | 处理中、刷新状态、返回活动；不要求重复点生成 |
| 真实确认后 | 给本人发送独立入口消息，正文带本期链接和“复制我的邀请链接/转发邀请/本群邀请记录”；不依赖反复刷页 |
| 确认时本人已在其他页面 | 入口消息自带活动/群身份及来源出口，不覆盖当前页面、不切回旧面板、不抢新草稿 |
| 明确失败 | 列具体原因/目标，按原资格提供明确失败人工重试 |
| UNKNOWN | 待核查、刷新/重新检测及返回；不自动重发或再生成 |
| 已截止/撤销/过期 | 标真实状态及原普通入群能力；无新增计奖引导，历史确认奖励保留 |

| 用途 | 统一按钮词 | 点击及文案边界 |
|---|---|---|
| 活动宣传 | 分享活动卡片 | 取得同款可转发公告；明确“宣传不计个人邀请”，不报名、不归因、不发次数 |
| 本人归因任务 | 我的邀请链接、复制我的邀请链接、转发邀请 | 本活动本人本群稳定入口；按门槛/奖励用途解释，只有真实新成员确认才累计 |
| 中奖联系 | 联系发奖人员、复制领奖联系信息 | 完整领奖说明与真实联系人同时可读；打开/复制不自动发消息，不推断领取完成 |

领奖复制模板优先保留同活动链接+本人Telegram ID+奖品顺位/名额，例如“活动：<同场链接>；本人ID：<ID>；奖品第<顺位>项，第<名额>个中奖名额”。完整活动名、奖品名和完整领奖说明留正文；不因长名称裁掉必要身份。

实施前核对原生复制文本的实际平台容量与SDK/客户端行为；本轮官方文档 `CopyTextButton.text` 为1–256字符，这是平台传输容量，不是领奖信息/名称业务上限。生成模板后按实际计量校验；不能把裁断链接或身份的文本放进“复制”按钮。最小必要模板仍放不下时明确提供正文完整模板手动复制，不伪装原生复制成功。[Telegram CopyTextButton](https://core.telegram.org/bots/api#copytextbutton)

复制是用户本人剪贴板动作，服务端不能由按钮存在推断已复制，更不能记录已联系/已发送。转发打开原生选择/提供本人可转发消息，必须由本人选择接收方并发送；Bot不代发给其他人。callback沿用服务端短token，官方范围1–64字节。[Telegram InlineKeyboardButton](https://core.telegram.org/bots/api#inlinekeyboardbutton)

## 8. 反馈：局部达标就知道，不增加领取步骤

通知完整继承[V3.0 §6](v3.0-participation-rules-and-feedback-prd.md#6-达标提醒个人进度与失败反馈)，不得为精简页面删掉主动反馈。

| 业务事实 | 必需反馈 |
|---|---|
| 本群当天发言门槛/邀请门槛跨阈值 | 该群即时形成通知意图，显示活动、群、北京时间事件日期/有效人数、局部完成和剩余门槛 |
| 全部行为门槛完成 | 最后一项对应群形成活动级完成提示；其他成员条件不合格仍说明不能参与开奖 |
| 发言/邀请正向奖励入账 | 本次增加、累计/今日奖励、当前有效或暂存；自动入账，没有“领取加成”按钮 |
| 同来源同时门槛/总体完成/奖励 | 同活动同用户同群同来源合为完整一条，保留各事件引用；通知用事务最终状态 |
| 日期/群/来源不同 | 分别通知，不跨日期/群合并；延迟送达写“完成时”事实和事件日期 |
| 截止仍未达标 | 排空截止前事实并复核后一次说明未完成项及本期结果，保留历史奖励记录 |

业务事实与通知意图同事务提交；重放Update、重启、重复验证不重复票或提醒。某群成功不等待其他群才提示；今日归零不抹本场完成。必要提醒不受精简扩展说明开关影响。

群通知、个人入口消息、宣传卡、群开奖结果与中奖私信分别记录Outbox/Attempt和真实结果；通知待投递/确认/失败/未知分开，客户端声音/弹窗另验。页面最新进度不能用延迟旧通知替代。

## 9. UP01–UP08 可执行核心路径

### UP01 首次创建至发布

路径：G01创建→C01下一项参与群→标题→C03名称/人数→C09门槛本群暂存/整场保存→C05时间→C16预览/确认→同活动C18投递状态。

- 成功检查：缺项逐项消失；时间在门槛明确后可核验；确认页共享公告与保存规则一致；规则页和主卡全部确认且强制窗口有效后才正式开始。
- 异常检查：无群有准备/检测出口；字段错误原值保留；无强制窗口明确原因不改期；UNKNOWN只核查；预览/看规则不创建第二场。

### UP02 多群规则、预设、复制与放弃

路径：C01参与条件/加成→群列表→本群数值+预设→明确保存→复制来源/选目标/确认→原列表→C01核对。

- 成功检查：群名/序号对应稳定群身份，升级后的当前路由不改变该身份；预设只替字段；门槛与奖励单位明确；复制只覆盖同类选定群；模块关闭时保存明确列所有恢复群。
- 异常检查：零目标不改数据；取消数字不丢其他值；放弃整场不丢其他稿；移除来源群原子清引用回列表；共享留存冲突有真实双方值，不能后写覆盖。

### UP03 草稿恢复、封面替换、复用与新建另一场

路径：C14上传/连续替换/完成→返回首页→继续同稿；C15明确载入上次；已有发布身份→同场C18；C17创建新抽奖→独立新稿。

- 成功检查：每次图片确认面板成为当前面板；完成回C14，清除仅封面；复用重设旧时间/身份；新场不占用或覆盖旧场恢复，21场以上也能查到旧场。
- 异常检查：离开封面后图片不误收；旧按钮不写当前稿；真实过期明确；创建结果未知查原幂等来源；已有未发布稿另建先明确继续/替换，不静默覆盖。

### UP04 看完整条件、明确登记、补齐成员条件

路径：群/转发卡同活动链接→M02完整条件/本人进度→明确登记→真实条件检查及普通加入入口→重新核验→M02。

- 成功检查：所有必需条件在登记前可读，翻页不报名；登记才形成本人意图，首次成员通过才启动本场统计；普通加入不归因个人邀请。
- 异常检查：私有入口/待审批/未知分别显示；长条件全部可达而不强制点完每页；换用户只见本人数据；缺条件有效0但历史完成/奖励仍可查。

### UP05 去本群发言、局部达标与午夜后回查

路径：M02内嵌进度→对应发言群详情→去本群发言→真实消息→群达标/奖励通知→返回M02看最新进度。

- 成功检查：普通入口真实可用；局部达标即提示；同来源多事件合一条含最终次数；今日和本场完成分别呈现；完成门槛不新增基础次数。
- 异常检查：入口不可用解释并保留返回；不补未观察历史；跨午夜/延迟通知不撤回本场资格；消息重放不重复计票，通知失败不隐藏业务完成。

### UP06 获取个人邀请入口并检查归因记录

路径：M02→我的邀请链接→本群明确请求→本人独立确认消息→复制/转发邀请→真实新成员/留存核验→本群记录及通知→origin返回。

- 成功检查：邀请门槛单开也可获取；确认消息不用反复刷页且不抢其他当前页；同场本人本群归因；记录/奖励按同事实更新，退群不扣已确认奖励。
- 异常检查：UNKNOWN无再生成；明确失败人工重试不混未知；过最晚计奖窗口不引导新增，既有待核验可读；单群直达返回来源，无总览自循环。

### UP07 宣传、开奖结果与本人领奖联系

路径：活动详情分享活动卡片→本人可转发公告；已开奖M02→完整结果/领奖说明→联系发奖人员或复制领奖联系信息→返回原参与列表。

- 成功检查：宣传不计个人邀请且报名链接同场；结果引用完成DrawRun/快照；模板含同场链接/本人ID/顺位名额，正文完整名称与说明保留。
- 异常检查：复制/打开联系人不发消息或登记领取；长名称不使原生复制失效；取消/缺快照不造最终0次；历史分享不续发开放任务引导；个人回执只投递本人。

### UP08 管理权限修复、取消与迟到投递

路径：C17我发起/我可管理→C18实时全群核验→故障群问题/真实修复检测→原状态；适用取消/截止/开奖/领奖→具体确认→真实状态回执及列表返回。

- 成功检查：缓存只候选，操作核验全参与群交集；权限阻断与人工暂停分别清晰；危险确认绑定原场/范围，结果与通知投递分开。
- 异常检查：失权可看公开记录但无敏感资料；修权限不自动恢复人工暂停；状态变化拒绝旧承诺；PUBLISHING取消保留UNKNOWN/Attempt，迟到卡确认后更新取消不重开；刷新不重发。
