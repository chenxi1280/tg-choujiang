# 无响应路径排查与修复（2026-10-09）

## 已定位的问题

1. 上一版仅保护了本人列表及成员导航。创建草稿、活动管理、报名反馈、中奖名单、规则分页、群内人品面板仍直接编辑消息；Telegram 明确返回 `message is not modified` 时可让有序 Inbox 重试并阻塞后续 `/start`。
2. 原页面被删除、不可编辑或原消息没有文本，原处理会重复编辑同一失效页面。现统一返回恢复提示，说明页面显示失败、已保存数据保留，并提供 `/menu` 恢复路径；不重建活动或重做已提交业务。
3. 开始点击时的空反馈已有 2 秒限制，实际结果反馈仍可能因网络错误抛出并重试整条业务。上一轮真实验收中 Update `162318017` 在 20:47:17 因连接重置失败，活动分享卡片 20:47:21 已确认送达，输入 20:47:24 才完成重试。现两种反馈都独立限制 2 秒，失败明确记录 `completed=False`。
4. 当前输入的界面回信被明确拒绝，例如用户屏蔽、账号注销、原聊天不存在、群内禁止文本提示，会反复失败。现只识别明确原因、限定界面 Send/Edit 方法及当前输入的来源聊天/回调本人；保留方法、目标、错误日志和 Inbox `last_error`，结束这一不可送达界面输入。`processed` 只表示输入已处理，不证明回信送达或业务成功。资格检查、其他聊天、内部错误、网络未知结果仍有序重试。
5. 机器人群权限提醒先发送再同步群状态，提醒被拒绝会阻止状态同步。现先完成状态同步，再发送提示；明确提示拒绝仍保留错误。
6. 单条业务处理原无总时限；停机可能留下 `processing` 等待 5 分钟才重领。现普通 app HTTP 请求限 15 秒，长轮询单独使用轮询时间加 10 秒，单条处理限 120 秒。超时保留失败并重试；正常停机或任务取消等待当前自有 claim 进入可重试状态，也覆盖处理已完成但状态投影尚未提交的取消窗口。同时核查到正常重启没有主动释放轮询租约，会等待旧租约到期才再次接收输入。现停机取消并回收长轮询请求后，仅令本人租约到期，保留 fence 与独占消费者约束；新消费者的租约不受旧进程迟到清理影响。强制断电/数据库不可达仍依赖原过期 claim/租约恢复。
7. 健康检查原只看轮询心跳，轮询正常但输入队列阻塞会被误判健康。现检查当前 Bot 最早未完成输入，超过 120 秒即报阻塞；界面回信拒绝单独统计，不作为消息成功事实。
8. 未识别旧按钮或无法访问原页面原只结束空反馈。现明确提示页面/按钮失效与恢复入口。
9. Outbox 卡片/规则编辑收到明确未改变响应时，现在以原远端消息 ID 记录 `unchanged=True`；原消息不存在或网络未知不会伪造确认，不另发替代卡片。

## 保持的边界

- Inbox 全局输入顺序、数据库先落地、业务幂等键、Worker 租约及不可变开奖快照保持。
- 报名、资格、发言统计起点、门槛与加成、开奖时刻没有调整。
- Outbox `UNKNOWN_HOLD` 不自动重发；没有清理生产失败记录或触发真实开奖。
- 当前检查覆盖已发现的具体错误路径，不能证明所有未来 Telegram、网络或数据库故障都不会发生。

## 验证

- Ruff 格式、Lint、代码规模检查通过。
- 上海 Docker 专用隔离库定向测试 140 项通过，覆盖重复编辑、失效面板恢复、有序重试、超时、停机、错误分类、队列健康、邻近创建/报名/导航/投递行为。首轮开发测试出现缩进错误，修复并重新传送源码后的完整定向运行通过；首轮不计为通过。
- 补充/最终定向测试 40 项通过（14.30 秒），包含群权限提示拒绝的状态保留与最终反馈超时；与前一组有重叠，不能相加声称 180 个不同用例。发布/浏览器证据在下文回填。

- 完整回归首轮拦截了参与记录反馈兼容问题：无文本的实际反馈需要显式 `show_alert=False`，不能与起始空反馈混用。保留该请求语义并统一限时、错误记录，修复后重跑记录隐私、回调反馈及完整回归；首轮发布未构建或上线。
- 修复后参与记录隐私/回调/页面恢复定向 57 项通过（6.91 秒）；轮询停机/持久化/Inbox 定向 19 项通过（17.05 秒），验证退出后请求已回收、新消费者可立即接管、fence 递增、旧进程不能释放新租约。
