# LotteryBestBot 逐项深度对比与验收合同

日期：2026-09-05。参考机器人为 @LotteryBestBot；本项目线上机器人经 getMe 确认为 @TGCCJBOT。

证据口径：**实测**是本次 Telegram 客户端真实点击或输入后的反馈；**说明**是目标首页所链接的原始频道说明；**代码/回归**是我们自己的实现与自动化验证；**线上**需要本轮部署后的 Telegram 消息与落库证据，不能用测试数量替代。对方后台不可见，不能推断其内部事务、随机算法或风控已经满足本项目要求。

## 1. 创建器：逐项和下级行为

本次 11:01–11:28 逐项进入目标真实草稿；只有无真实奖品的测试草稿，清空检查后恢复“测试奖品 × 2”，未发布到第三方群。

| 项目及叶子 | 目标的实际表现 | 我们的实现、差异与检查位置 |
|---|---|---|
| 新建/继续 | `/new` 打开成品预览，已有草稿可继续 | `campaign_creator`：草稿身份、修订、面板绑定，旧面板恢复；发布请求幂等 |
| 标题 | 必填，提示不超过80字；缺标题点发布弹窗阻止 | 1–80字，缺项集中说明；数据发布前再校验 |
| 封面 | 选填，发送图片，置于活动顶部 | 接收 Telegram photo file_id，可清除；非图片明确报错；与活动卡一同发布 |
| 用户名限制 | 可为空/必须设置，默认可为空 | 用户名要求随规则冻结，报名与开奖复核同口径 |
| 地区限制 | 全国或省级选择，最多3项 | 省份限制、归属地设置和锁定均存在；不是根据 ID 推断地区 |
| 必须加入的群和频道 | 一次录入一个，可重复添加；公开可用户名或ID，私有要求ID | 支持链接、来源可见转发、用户名及高级ID输入；可一次多项；按真实名称展示 |
| 多个活动群 | 目标公开样例可包含多个群，分别列条件 | 本项目额外区分“发活动卡的参与群”和“仅作准入的群/频道”，两类都必须全部满足 |
| 逐群发言门槛 | 公开活动卡显示每群不同发言条件 | 每群至少 N 条，频道不可设发言门槛；与可选发言加成分离，不将额外只读准入群误判为加成群 |
| 组合分享链接 | 参与条件下的独立子页；明确不改变实际参与条件 | 本轮新增设置、清除、格式检查和活动卡按钮；冻结链接，不跳过逐项资格核验 |
| 奖品名称 | 名称建议10字以内，可以持续添加 | 允许1–120字；每次名字后输入正整数数量，保持顺位 |
| 删除指定奖品 | 进入带奖品名称的编号列表，再输入编号 | 原来只能删末项，本轮修复成指定编号，可一次多项；保留剩余顺序 |
| 清空奖品 | 独立清空入口 | 提供独立清空；重进奖品页也能发现删除/清空按钮 |
| 抽奖说明 | 选填文本 | 独立说明字段，展示时转义用户文本 |
| 定时开奖 | 年-月-日 时:分，示例按当前日期 | 同格式，显示活动时区；增加快捷时间；5分钟结算窗口明确纳入时间校验 |
| 满人开奖 | 当前普通账号输入0被拒绝，反馈1–300；说明30天后中午自动开奖 | 正整数人数，不复制商业账号300人配额；达到合格人数后进入结算，30天中午兜底 |
| 发奖人 | 默认创建者，可输入用户名或ID | 默认显示名字；解析真人身份并冻结用户名/显示名，数字只作为高级输入 |
| 人品总开关 | 可开/关，提示影响中奖概率 | 我们为“抽奖加成”，分别配置邀请和发言，关闭后仅基础次数 |
| 人品票数上限 | 额外票数配置，建议不超过3 | 我们按本场逐群奖励与封顶配置；不把长期积分当作本场邀请奖励 |
| 每群人品成本 | 每群独立消耗，可为0；兑换一票同时扣各群积分 | **产品机制不同**：我们按有效邀请/有效发言直接累积本场票数，无永久积分消费账户 |
| 消息清理 | 同步删除口令独立开关；10/20/30秒、1/5/10/30/60分、不删除；当前选中10分 | 同样时间档位，分别控制报名命令和完成提示；我们默认保留，尊重已有草稿配置 |
| 发布前校验 | 缺标题立即阻止；按步骤补齐 | 我们复核所有参与群/准入条件/发奖人/加成权限，确认规则后投递 |
| 清空全部配置 | 实测点击立即清空并提示完成 | 我们保留二次确认，防止误触丢掉草稿 |
| 载入上次抽奖 | 无历史时明确提示没有历史 | 恢复上次草稿并重新解析群/频道与权限；不复用旧场邀请归因 |
| 返回与旧面板 | 返回子菜单/首页；旧历史按钮可能不响应 | 草稿状态保留；过期回调恢复到当前面板，不重复发布 |

## 2. 参与：沿着资格事实检查

| 叶子行为 | 本项目应有结果 | 当前可复现依据 |
|---|---|---|
| 群内点击立即参与 | 按点击者身份核验，可直接弹窗反馈 | `member_flow`、callback 路由测试 |
| 私聊参与入口 | 与群内入口收敛到同一登记与资格服务 | 公共引用路由测试，不依赖 UUID 文本输入 |
| 少一个参与群 | 拒绝报名，指出缺失群名 | 多群报名/复核回归 |
| 少一个必须关注频道 | 拒绝报名，显示“关注频道”与入口 | 条件页和成员观测回归 |
| 条件较多 | 分页完整展示，不能只校验第一页 | 条件分页与资格目标集合测试 |
| 加入申请未批准 | 显示等待批准，不能记为已加入 | pending 与 unknown 独立分支 |
| Telegram 无法核验 | 显示待核验/异常，不伪装参与成功 | qualification、outbox、inbox 回归 |
| 发言等于门槛 | 按“至少 N 条”允许，前台与核验一致 | 本轮文案与阈值回归 |
| 重复点击报名 | 不重复基础票、不重复计数 | 登记幂等与账本唯一键 |
| 已报名后退群 | 开奖前仍按冻结目标复核 | qualification review、settlement 测试 |
| 我的记录/加成回调 | 查询点击者，不能查到 Bot 自己的身份 | 本轮修复并有 `test_personal_callback_identity.py` |
| 同名活动 | 名称、列表序号、开奖时间区分，按钮仍绑定精确活动 | 本轮清除用户界面随机短码 |

## 3. 用户新增要求：逐场逐群邀请的生命周期

目标人品说明不能证明它具备以下邀请合同；下列是本项目独立需求，不能遗漏或换成长期积分。

| 边界 | 约定 | 验证要点 |
|---|---|---|
| 身份范围 | 每场抽奖 × 邀请人 × 目标群独立路由 | CampaignReferralRoute/InviteLink/Invitation 的归属一致 |
| 多群奖励 | 各群独立门槛、每档奖励与封顶 | 前台读冻结的 group_invite_rules，不读旧全局默认值 |
| 有效邀请 | 新成员真实入群并达到本场留存/资格要求才奖励 | 点击、已有成员、自邀、重复事件不能计奖 |
| 留存等待 | 本场可选立即核验、24小时、48小时；明示待验证与生效时间 | 到期 Job 真实 getChatMember 后结算，立即核验也不能绕过资格 |
| 截止前后 | 截止停止本期归因与奖励，展示明确截止时间 | 迟到事件与跨截止检查 |
| 链接持久 | 新本期邀请链接无 Telegram expire_date；开奖不撤销 | 持久属性、截止后落地页与正常入群单独验收 |
| 不跨下一场 | 旧路由仍指向原活动，不改绑新活动 | 同群多场并行与旧路由去往新场的负向测试 |
| 旧链接真的已过期 | 明确告诉用户，不伪装仍可用；可按规则换底层版本 | 本轮补过期版本轮换，外发稳定入口不改 |
| 群公开入口 | 有可用普通入群地址时明确仅供加入，不冒充计奖入口 | 落地页显示本场状态、群名与奖励停止说明 |
| 账本核对 | 次数来自已确认的奖励事实 | 不能用“链接已创建”替代“邀请已获奖” |

## 4. 后台指定与前台正常公布

用户确认语义为“后台指定，前台正常展示中奖结果”。

| 叶子 | 实现 |
|---|---|
| 后台授权 | 独立运营 Bot 私聊白名单；本轮增加经过服务器身份验证的控制台，同一 OPS_ADMIN_IDS 白名单 |
| 列活动/奖项/名额 | 名称加管理员使用的精确引用，设置前可查看已有指定 |
| 指定对象 | 本场已报名用户，支持用户名或高级用户ID，不新建假参与者 |
| 同一奖项不同名额 | 精确绑定顺位和名额，避免随机名额提前用掉后面被指定的人 |
| 最终资格不合格 | 明确阻止开奖并保留指定记录，不静默改派中奖者 |
| 撤销/替换 | 限允许编辑的状态，记录前后对象和操作人 |
| 审计 | Bot 与服务器控制台分别记录来源；结算快照记录最终选择方式 |
| 前台结果 | 指定者正常出现在中奖名单与本人通知；公开 Bot 不注册后台命令，不显示指定操作入口 |

## 5. 帮助、导航与精选：区分入口和运营流程

本轮创建并配置了使用说明、活动导航、精选推荐三个自有测试频道；内置指南覆盖创建、权限、多条件报名、逐场邀请、开奖与领奖。

目标首页 2026-09-05 仍指向原导航说明。已实际打开并读到：人工巡检发布；达到运营门槛的活动可入导航；运营人员提升客户等级后，进行中活动可自行发布，每日有配额；违规可降级，撤销已推导航的抽奖也会被运营处理。这是一套人工运营和权限产品，**仅有频道跳转不等于具备这套流程**。

本项目目前有自有说明与三个频道入口；没有复制其客户收费等级、永久人品积分/排行/管理员加减分，也尚未实现对应的导航投稿审核与精选商业推广。目标的地域/群规模/商业奖品门槛不作为我们新增的准入限制。它的管理后台及付费客户专属分支不能从普通账号菜单推定已完整实测。

精选原始说明也已从目标首页真实打开：除基础群规模门槛外，要求现金累计300以上或等值奖品；定时活动20天内开奖，满人活动门槛低于200且排序靠后；已结束活动关闭入口。本项目不直接套用这些商业筛选门槛；频道跳转、人工运营与自动关闭入口须分别验收。

## 6. 过去故障与本轮修复

| 问题 | 修复/检查 |
|---|---|
| 原始群ID和随机活动短码占据默认UI | 名称、自然序号与时间；技术引用仅保留在回调与后台 |
| 回调读取 Bot 自身用户 | 按实际点击者查询个人中心 |
| 加成页与冻结逐群规则不同 | 发布卡、规则、私聊、邀请页使用相同逐群规则展示 |
| 只读准入群被错误要求可发言 | 仅为实际启用发言规则的群检查发言权限 |
| 私有入口成功但卡片未接力 | 既有 autoflush 修复保留；本轮补投影幂等，不重复生成活动卡 |
| 入口生成失败在管理页不可见 | 本轮同时列出入口生成与活动卡发送阶段，展示真实目标名和中文原因 |
| 上次模板丢失多群规则 | 本轮补齐保存字段，旧活动和面板身份不被复制 |
| 短时活动无法获取邀请 | 新增本场留存选择，默认不变，可显式选立即核验并走真实资格验证 |
| 过期活动仍可以点重试发布 | 本轮阻止超过截止时间的发布恢复，提供取消后新建的明确提示 |
| 远端 UNKNOWN 被当普通失败重发 | 原远端事实约束保留，只重试 PRE_ACCEPT_FAILED |
| 空文本 update 造成队列头阻塞 | 既有修复及回归保留，线上按 Inbox 最新处理时间和错误核对 |
| 发布提交与真实发帖混淆 | 只有各群 message_id 确认才开始，线上核对每群投递事实 |
