## 1. 已补设计遗漏与代码

| 发现的遗漏 | 本轮补齐 |
|---|---|
| 群内查询没有路由、排行口径未确认 | 用户确认按本场活跃入账次数排行；人品/规则/排行只读，多场先选，10人分页，同分并列，包含暂存并解释资格区别。查询不计数、不报名、不发票；不引入永久积分、兑换或管理员改分 |
| 查询泄露未发布草稿/旧按钮范围不清 | 过滤草稿/发布中场次，绑定原群、活动与查询者；旧活动规则可读，关闭加成和空榜有说明，同名旧群进度按稳定ID读取 |
| 私有群名指向泛化入口 | 与本人条件页共用冻结目标顺序，公开群名深链定位同场同条件，不公开原始私有邀请 |
| HTML链接长度误作消息容量、长说明不能安全分页 | 以HTML显示后的UTF16计容量；文本先安全分段再转义，保留标签/链接，完整页有活动名、页码和同场入口，主卡仍按条件→奖品→说明→加成→时间 |
| 部分旧模板缺少编辑字段 | 模型补默认值，保留有效阈值和奖励，转换新场无上限且24小时；已发布规则不变 |
| 平台规则只有设计和跳转URL | 显式配置策略默认关闭；三个角色不同稳定ID，Bot身份/加入URL/管理员权限校验；私有官方频道校验邀请权限；规则冻结、目标来源合并、只读说明、发布前再复核及变化重新确认 |
| 启动/屏蔽事实缺持久化、私聊成员事件被当群事件 | 新增Bot关系表；/start事实先提交，响应失败不回滚；私聊成员事件独立处理，同秒冲突不按ID大小猜先后；只恢复保留的已处理本人私聊事实，缺证据提示补录 |
| 新平台复核沿用旧降级路径 | 新策略故障保留阻断；有限相关Inbox水位、300秒观察期、过期补查、关系/地区变化重查；已投影的普通/start或纯查看响应失败不替代业务事实，其他业务事件仍按原Inbox/Outbox处理 |
| 确定未过门槛者仍等待无关平台查询 | 明确记录行为排除，保留成员状态，不让排除检查阻止截止前合法消息投影；未收敛消息/邀请仍由原结算排水阻断 |
| 最终资格只重查成员，缺用户名/地区 | 按已有配置重查实际用户名信息及数据库地区，缺信息/冲突不伪造通过；保存观察和明确失败原因，新平台快照前地区变化触发复核 |
| 无上限累计/个人快照使用32位整数 | 五项累计/个人权重扩大为64位，支持3,000,000,001权重的实际SQL冻结；不改变票账delta、每轮公式、抽奖算法或已有票数，缩窄会溢出时拒绝回退 |
| 定向执行器未先迁移导致缺表及清表失败 | 定向pytest也先升级并检查同一专用库；保留身份核验、flock、全量八分片及每进程60秒硬限 |

本轮未将平台条件施加给受邀人。有效邀请仍为同一稳定群、同一Telegram用户只算一次、满24小时并核验真实成员；已确认邀请及奖励保留。平台条件检查参与者本人，获取新的邀请入口先复核本人条件，历史记录保持可读。
