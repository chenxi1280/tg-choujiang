# TG 群抽奖机器人 V2.3 参与者按钮与记录交互合同

状态：本地核心交互实现与自动化验证完成；部署和真实 Telegram E2E 未执行

日期：2026-08-19

实现说明：私聊首页、按活动参与记录、按活动邀请记录、逐群邀请入口、稳定外发落地页、截止前后按钮与记录分页已接入。界面文字和 Telegram 实际按钮渲染仍以真实客户端 E2E 为最终证据。

主产品合同：[V2.3 用户邀请与同群多活动整体 PRD](v2.3-user-invitation-multi-campaign-prd.md)

本文规定参与者页面、按钮、分页、空态、截止状态和失败恢复。业务归因、时间、计票、数据与迁移语义以主 PRD 为准；两者冲突时先修正文档，不允许实现自行选择。

## 1. 完整导航

~~~
群活动卡
├─ 立即参与本次抽奖
├─ 参与条件
└─ 我的加成（私聊深链，绑定 Campaign）
   ├─ 邀请加成
   │  ├─ 逐群列表
   │  ├─ 单群本期入口
   │  └─ 单群邀请记录
   ├─ 发言加成
   │  └─ 逐群今日/历史进度
   └─ 抽奖次数明细

机器人私聊首页
├─ 我参加的抽奖
│  ├─ 进行中
│  ├─ 待开奖
│  └─ 已结束
├─ 我的邀请记录
│  ├─ 按活动
│  └─ 按群和状态
├─ 发起抽奖
└─ 我创建的抽奖
~~~

每一层都必须有返回上一级和回到本次活动的按钮。用户不需要翻找旧消息恢复入口。

## 2. 通用按钮规则

- 所有参与者回调绑定 Campaign 公共短引用和点击用户；群维度操作还必须绑定 ParticipationGroup。
- 服务端联合校验 Campaign、Participant、当前 Telegram 用户和目标群，不能返回他人链接或记录。
- 同名活动始终显示短编号和开奖时间；同名群显示 username 或 chat ID 尾号。
- 群列表每页 6 项，记录每页 10 条；越界返回有效最后一页并提示列表已变化。
- 旧按钮指向仍存在的活动时打开最新投影；活动或群已不可用时显示真实终态和可用返回路径。
- 回调先结束 Telegram loading，再查询或重绘；重复 Update 不创建第二条路由、链接版本或票。
- UNKNOWN 只提供“刷新/重新检测”，不提供会盲目重复创建远端链接的按钮。
- Telegram 没有真正禁用按钮；不可用动作写在正文状态中，不显示假按钮。

## 3. 群活动卡

同一群有多个活动时，每张卡必须带活动身份：

~~~
🎁 八月会员抽奖 #7K3M2Q
截止：08-25 20:00
开奖：08-25 20:10

[🎟 立即参与本次抽奖]
[📋 参与条件] [🔋 我的加成]
~~~

“我的加成”始终进入该卡所属 Campaign。未报名时落地页先解释并提供“立即参与”；已报名但资格待补时进入参与条件；已合格时进入加成页。未开启任何加成时隐藏“我的加成”。

邀请加成没有“领取”按钮。邀请达到对应群门槛后自动写入票账本；页面的“刷新状态”只读最新结果，不触发补发或重复计票。

## 4. 私聊首页

私聊首页同时服务参与者和创建者：

~~~
[🎟 我参加的抽奖] [👥 我的邀请记录]
[➕ 发起抽奖]     [🗂 我创建的抽奖]
[设置]            [帮助]
~~~

空态：

- 未参加活动：“你还没有参与抽奖”，并提供“返回首页”。
- 没有邀请记录：“还没有可显示的入群记录。参加开启邀请加成的活动后，可从单群页面分享本期链接。”
- 有参与记录但没有邀请加成：参与记录正常显示，不生成邀请入口。

[八月会员抽奖 #7K3M2Q｜12票｜合格]
[周末抽奖 #91AB4C｜待补1群]
[上一页] [下一页]
[返回首页]
~~~

状态：进行中
资格：合格
总抽奖次数：12
报名：1；邀请：8；发言：3
截止：08-25 20:00

[我的加成] [抽奖次数明细]

## 6. 我的加成

同时开启两类加成时先选分类；只开启一类时直接进入对应列表：

~~~
🔋 八月会员抽奖 #7K3M2Q · 我的加成

[👥 邀请加成｜8次]
[💬 发言加成｜今日3次]
[🎟 抽奖次数明细]
[返回本次抽奖]
~~~

邀请群列表：

~~~
[A 群｜有效5｜+2｜链接可用]
[B 群｜等待1｜+0｜生成链接]
[C 群｜已截止｜仅可入群]

## 7. 单群邀请详情

截止前：

~~~
👥 A 群邀请加成
活动：八月会员抽奖 #7K3M2Q
规则：每2名有效新成员 +1；不设上限
最晚计奖入群：08-25 19:30
有效5；等待1；未计入2；已获得2次
距下一次：1人

[复制本期邀请链接] [转发邀请]
[邀请记录] [刷新状态]
[直接打开 A 群] [返回群列表]
~~~

底层链接状态对应按钮：

| 状态 | 展示和动作 |
|---|---|
| not_created | “尚未生成”；“生成本期邀请入口” |
| creating | “正在生成”；“刷新状态” |
| active_bonus | 复制、转发、邀请记录、打开群 |
| active_join_only | 复制/转发按钮明确标注“不计加成” |
| permission_failed | 查看具体原因、重新检测；不展示 URL |
| retryable_failed | 明确失败后可重试 |
| unknown_hold | 仅核验状态，不盲目创建 |
| revoked | 展示撤销原因；可用时走普通入群入口 |

截止后：

~~~
本期加成已结束。该入口仍可用于加入 A 群，
新入群不会增加本期抽奖次数。

[复制入群链接（不计加成）] [转发入群]
[查看历史邀请记录] [打开 A 群]
[返回本次抽奖]
~~~

截止前从未生成个人入口时，截止后不再创建无归因意义的个人底层链接，按钮直接使用活动普通入群入口。

## 8. 受邀人落地页

截止前：

~~~
你收到一位好友的邀请
活动：八月会员抽奖 #7K3M2Q
目标：加入 A 群
加入 A 群只完成一个群条件；参加抽奖还需报名并满足全部参与条件。

[加入 A 群]
[查看全部参与条件] [报名本次抽奖]
~~~

截止后同一外发入口显示：

~~~
本期抽奖加成已结束
你仍可通过此入口加入 A 群，但不会再给邀请人增加本期次数。

[加入 A 群]
[查看开奖结果]
~~~

活动取消时显示取消，不继续宣传“参加本次抽奖”；权限故障时显示目标群和具体不可用原因。页面不公开邀请人的 ID、username 或昵称。访问落地页不代表有效邀请。

落地页确认用户已经是目标群成员时显示：

~~~
你已经是 A 群成员
本次打开不会产生新成员邀请加成。

[打开 A 群]
[查看/报名本次抽奖]
~~~

该确认可写入邀请人的“未计入”记录；Telegram 核验 UNKNOWN 时显示“暂时无法确认”，不能写成已是成员。

## 9. 我的邀请记录

全局入口先按活动聚合，进行中优先：

~~~
[八月会员抽奖 #7K3M2Q｜有效8｜等待1｜+4]
[周末抽奖 #91AB4C｜有效3｜已结束｜+1]
[上一页] [下一页]
~~~

进入活动后先选群；单群页提供筛选：

~~~
[全部] [等待中] [有效] [未计入]

张* · ID尾号 4821
08-19 14:20 入群｜留存核验中，预计 14:50

李* · ID尾号 1037
有效｜计入 A 群有效人数

王* · ID尾号 6620
未计入｜加入前已是本群成员

[上一页] [下一页]
[返回群列表] [返回本次抽奖]
~~~

每 N 人增加一次时，不把单个人标成“贡献 +1”；个人资格记录与群级已获得次数分开显示。

当某群达到新门槛并实际新增抽奖次数时，机器人给邀请人发送一条可去重通知：“A 群有效邀请达到 6 人，本期自动 +1 次”。截止前退群导致已发目标冲正时也发送一次对应说明。单纯访问链接、等待审批或每一条普通状态变化不逐条刷屏。

## 10. 用户状态文案

| 稳定状态/原因 | 用户文案 |
|---|---|
| join_request_pending | 已申请入群，等待群管理员批准 |
| joined_pending_retention | 已入群，留存核验中 |
| checking | 正在核验 |
| valid_provisional | 当前有效；截止前退群仍会冲正 |
| valid_frozen | 已在截止快照确认有效 |
| left_before_valid | 留存期内退群，未计入 |
| left_before_cutoff | 截止前退群，已冲正 |
| existing_member | 加入前已是或曾是本群成员 |
| self_invite | 自己邀请自己，不计入 |
| bot_account | 机器人账号，不计入 |
| after_bonus_deadline | 已超过本期最晚计奖入群时间 |
| wrong_group_or_link | 链接与实际群不匹配 |
| validation_unknown | Telegram 暂时无法确认；等待恢复 |

UNKNOWN 不能归入“未计入”终态筛选，必须单列等待状态。恢复后重绘原记录，不另建一条邀请。

活动详情的票数明细按来源和群展示：

~~~

报名：1

  A 群 +2｜B 群 +6
发言：3
  A 群今日 +1｜B 群今日 +2

历史活动使用截止快照，不把当前时间的群成员状态重新套用到旧结果。

## 12. 隐私、分页和恢复验收

- 邀请人只能查看自己的记录，创建者按运营权限查看活动汇总。
- 默认展示脱敏昵称和用户 ID 尾号，不显示手机号。
- display name 只保存必要事件快照；归档后的明细依数据保留策略匿名化，聚合账本保留。
- 翻页、筛选和返回都保留 Campaign 与群上下文。
- 用户从任何旧活动卡进入，都显示该活动真实状态并能返回私聊首页。
- 底层链接轮换后，已复制的稳定外发入口仍能打开当前页面；不要求用户重新分享。
- 机器人无法私聊用户时，群卡深链负责让用户主动开启会话；失败提示不得宣称已发送私聊。
