# 公告与转发卡片样式（2026-10-05）

本条款覆盖 V3.0 PRD 的主卡排版与活动分享入口。参考用户提供的 Telegram 消息截图，
使用原生图片说明及 HTML 链接；行为门槛、加成、报名、邀请归因与开奖合同继续沿用原规则。

2026-10-07后续覆盖以 [V3.3 统一PRD（R5）](v3.3-unified-participation-and-reputation-prd-20261007.md) §6.3、§11、§20为准：新场双加成无上限；主卡条件后紧接独立奖品列表，再放说明、加成和开奖。长说明优先移到完整规则，保留主卡完整条件/奖品；核心本身超限时保留奖品预览与剩余数量，完整条件/奖品逐项进入有序页，不隐藏奖品区或截断名称。短卡、分享卡与规则页同源，旧验证记录不代表本轮已发布。

## 主卡排版

有封面时发送一条原生图片消息，图片在上，正文在下；无封面时发送同模板文字消息。

1. Emoji 与加粗活动标题。
2. “参与条件（必须全部满足）”：各群/频道名称可点击；对应行为门槛紧接该目标并以 `└ 🎟️` 缩进。
3. 奖品名称与名额。
4. 抽奖说明，保留创建者原始换行并转义 HTML。
5. “人品加成”展示实际开启模块；“规则”链接进入同活动完整规则。
6. 报名及行为统计截止、开奖日期均使用北京时间，显示至秒。
7. 发奖人员（已配置时）及可复制的活动参与链接。

底部主按钮为“👉 点击参与抽奖”，与正文链接使用同一 `join_<活动ref>`。
已有组合群文件夹链接继续提供独立按钮。主卡不显示虚构的个人加成次数。

发言门槛使用“满 N 条/至少 N 条”，保持原包含边界；不会把配置的 5 条改成“大于 5 条”。
新每日门槛显示每日条数、连续天数与有效字符要求；历史累计门槛继续标明累计。
邀请门槛只显示有效邀请要求，不混入发言门槛；独立加成的详细规则在规则页展示。
私有群/频道在公开卡中只显示本活动 Bot 入口，不公开实际私有邀请链接。

## 分享与转发

发布回执和开放活动的条件页提供“获取分享卡片”，进入 `share_<同活动ref>`。
该入口只向请求者本人的 Bot 私聊发送同封面、同排版、同活动链接的原生卡片，
不登记 Participant、不发基础次数、不改变邀请归因。

群公告和私聊卡片显式设置 `protect_content=False`。用户可长按原生卡片转发，
正文包含可点击群名、规则链接与参与链接；转发后即使客户端未保留底部按钮，也保留正文入口。
群/频道自身的内容保护限制及 Telegram 客户端实际转发结果需要独立验收。

分享请求使用当前 Update 身份作为业务幂等键，通过现有 Outbox 投递；重复处理同一 Update
不重复发卡。明确失败和结果未知沿用现有投递状态，不把入队当作 Telegram 已送达。
请求后若活动截止或进入非开放状态，实际投递前补充当前状态，按钮改为历史规则入口。

## 长文与完成边界

长度按 Telegram 解析 HTML 后的可见文字计量，长链接属性不误占图片说明正文容量。
保留既有容量预留。主卡超长时明确提示查看完整规则；同次发布的全部规则页确认后才投递主卡。
分享长文卡通过同活动的“规则”链接读取完整条件，不依赖接收者能访问原活动群的规则消息。
不会裁切单个条件、拆开 HTML 链接或以卡片成功替代规则页确认。

代码与自动化验证不代表生产已更新，也不代替真实客户端转发与提醒结果的验收。
