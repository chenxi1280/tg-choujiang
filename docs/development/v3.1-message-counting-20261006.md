# V3.1 发言计数口径调整

本合同覆盖 V3.0 及更早版本的发言最低字数和消息类型条款。

- 发言门槛、每日发言加成及旧累计门槛不再要求每条最低字数；一个字、纯表情、图片、贴纸及 GIF 表情均可计数，图片无需文字说明。创建器移除最低字数设置，公告、分享卡和规则页移除“每条至少 N 字”提示。
- 新口径应用于更新后收到的消息，包括正在进行的历史活动。历史规则 JSON 中的 `min_text_length` 仅为读取兼容保留，不再参与判定；不改写原规则、不补算已拒绝消息、不更改历史票数或开奖快照。
- 仍按本人消息、对应活动/群、登记与资格通过后的统计起点、北京时间自然日及活动截止判断。命令、机器人、服务消息、转发和空白消息不计数。各群门槛和加成独立统计，条数、天数、奖励与每日上限保持原设置。
- 同一 Telegram 消息重放仍只计一次。文字沿用大小写与空白归一去重；媒体使用消息类型、Telegram `file_unique_id` 和归一后的说明组成内容标识。不同图片或贴纸可以分别计数，相同媒体及说明按已有重复窗口处理；旧累计统计沿用连续重复内容只计第一条。图片组中的每个 Telegram 消息分别处理。
- 受邀人活跃消息统计共用有效消息判定，同样采用新口径；有效邀请的其他要求保持原设置。

验收覆盖短文字、纯表情、无说明图片、贴纸及动画表情；不同媒体、重复媒体、同消息重放；命令/机器人/服务/转发/空白排除；门槛达标、加成入账、旧累计计数及展示一致。隔离自动化检查与真实 Telegram 计数验收分别记录。

## 首次实施时的验证记录

- 上海 Docker 定向测试 56 项通过，覆盖有效消息判定、媒体识别、计数/达标/入账、去重、累计统计及消息入口。
- 完整回归首次在旧“纯符号消息不计”文案断言处失败；更新为新计数口径后重跑，前七个分片共 735 项通过。最后分片的 104 项受测试服务器磁盘耗尽影响，出现 `DiskFullError: No space left on device`，该分片及完整回归不能计为通过。
- Alembic 升级、检查、回退到 base、重新升级和再次检查通过。Ruff 格式/静态检查、代码规模检查及 `git diff --check` 通过。
- 只读核查确认上海测试机根分区 100%，可用空间为 0；清理本次三个可重建测试镜像后仍无可用空间。其余占用包括其他任务目录，未删除其他任务的文件或数据库资源。
- 尚未部署到生产，也未完成真实 Telegram 客户端计数验收。

上述保留首次实施时的失败及环境边界；接续已发布且完成有限真实 Telegram 计数验收，具体版本、消息与账本证据见[V3.2 实现与验收记录](v3.2-implementation-and-acceptance-20261006.md)。跨午夜和多日真实场景仍不能据此计为通过。
