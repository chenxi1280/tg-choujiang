# Inbox 同类故障修复与代码审查（2026-10-26）

## 处理范围

保留整个 Bot 的输入顺序、业务幂等和未知结果保护，不改为跨聊天并发。

- 来源界面回信遇到 TOPIC_CLOSED、message thread not found 时记录明确拒绝并结束该输入；只匹配原来源、既有 UI 方法和精确错误，不覆盖资格读取或跨聊天请求。
- 旧管理员事件读取当前管理员列表时，只有明确 Bot 已被踢出/不在成员中的 Forbidden 才撤销本地 GroupAdmin 缓存，随后记录 Bot membership unavailable 并继续处理。网络错误、含糊权限错误、撤销写库失败仍失败重试；不根据失败捏造资格或送达。
- Inbox 的 TelegramRetryAfter 与资格层 QualificationRateLimited 使用持久 next_attempt_at，重启与重新 claim 不绕过截止时间。长轮询层也等待 retry_after，停机可中断等待。
- 新增 last_failure，普通失败重试成功后仍保留最近的失败原因；last_error 继续表达当前失败或终结拒绝，不混用健康统计。
- 健康脚本将 UI 回信拒绝与成员身份失效分别统计。

## 数据与回滚

迁移 c33a1026ir01 仅新增两个可空字段并回填现有 last_error，不改变业务活动、资格或开奖数据。存在未来的限流截止时间时禁止降级删列。运行制品回滚也不能绕过持久限流截止时间；详见部署合同。

## 四维审查

- 正确性：覆盖真实 handler、真实隔离数据库权限撤销、后续输入推进、普通晋升/私聊屏蔽不回归、错误匹配边界；结束事件不等于提示送达。
- 性能：沿用顺序查询，仅增加失败行截止时间判断；限流不再每五秒发送请求，等待不占用数据库事务。未引入额外队列并发。
- 可维护性：把 Bot 成员投影提取为独立模块，明确拒绝与未知失败分开；保留失败诊断字段，健康指标区分原因。
- 安全性：权限撤销完成之前绝不终结；资格未知、跨聊天错误、网络未知仍保留，不扩大公开 Bot 运维权限。

## 验证记录

- 20 项定向测试在上海专用 Docker 执行器通过：原事故、限流重启/边界/再次限流、失败原因保留、权限撤销及其失败、来源范围保护、迁移回填与降级保护、长轮询等待和停机。
- 原诊断的过期管理员样本缺少 can_send_welcome_messages，曾在解析阶段失败；已在检查文档中更正原动态复现结论。正式测试补齐字段，并验证 GetChatAdministrators 真正执行，失败类型与预期一致。
- 其他回归与最终版本结果随执行记录追加；证据目录 artifacts/inbox-hardening-20261026/。

## 边界

此次防护不意味着任意未知异常都能自动跳过。严格全局顺序仍可能因真实业务/数据库错误阻塞；健康检查仍会明确报告。未在生产制造踢群、话题删除、限流或开奖。
